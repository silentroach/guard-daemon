# Конфигурация guard-daemon

Это полный справочник поддерживаемых переменных окружения. Конфигурация
проверяется при запуске; отдельной команды для её проверки нет. Пример
[`.env.example`](../.env.example) намеренно содержит заглушки и не готов к
запуску.

## Источники значений

Необязательный файл `.env` читается из текущего рабочего каталога. Systemd unit
задаёт `GUARD_DAEMON_CONFIG=/etc/guard-daemon/guard-daemon.env`, поэтому служба
читает публичную конфигурацию по этому фиксированному пути после запрета core
dump. Допустимы только строки `NAME=value`, пустые строки и комментарии. Формы
`NAME: value` и `export NAME=value` отклоняются до разбора значений. Если поле
задано и в окружении процесса, и в `.env`, значение из окружения процесса имеет
приоритет.

`SOURCE_PRIVATE_KEY` и `SPONSOR_PRIVATE_KEY` являются исключением: строки с
этими именами пропускаются при чтении `.env`, а одноимённые переменные начального
окружения процесса запрещены. Поддерживаемый systemd unit передаёт значения через
`LoadCredential` из `/etc/guard-daemon/credentials/source-private-key` и
`/etc/guard-daemon/credentials/sponsor-private-key`. Binary читает credential
files только после `RLIMIT_CORE=0` и `PR_SET_DUMPABLE=0`. В dry-run и emergency
их значения не разбираются и не сохраняются в конфигурации.

Неизвестные имена в зарезервированных пространствах `RPC_*`, `RESCUER_*`,
`TOKEN_*`, `NETWORK_*`, `SPONSOR_*`, `STATE_*` и других пространствах схемы
вызывают ошибку. Ошибка называет поле, но не выводит его значение.

## Общие поля

| Поле | Значение по умолчанию | Требования |
|---|---|---|
| `DRY_RUN` | `true` | Только `true` или `false`. Значение `false` выбирает live-режим. |
| `EMERGENCY_STOP` | `false` | Только `true` или `false`. Действует совместно с `DRY_RUN=false`. |
| `SOURCE_ADDRESS` | нет | Обязательный ненулевой EVM-адрес наблюдаемой роли source. |
| `SPONSOR_ADDRESS` | нет | Обязательный ненулевой EVM-адрес роли sponsor, оплачивающей комиссии. |
| `DESTINATION_ADDRESS` | нет | Обязательный ненулевой EVM-адрес безопасной роли destination. |
| `ENABLED_NETWORKS` | нет | Обязательный непустой список имён сетей через запятую. Имена должны быть известными, неповторяющимися и записанными в нижнем регистре. |
| `SOURCE_PRIVATE_KEY` | нет | В live без emergency обязателен как systemd credential `source-private-key`. Валидный приватный ключ secp256k1: 64 шестнадцатеричных цифры, необязательный префикс `0x`. |
| `SPONSOR_PRIVATE_KEY` | нет | В live без emergency обязателен как systemd credential `sponsor-private-key`. Формат совпадает с `SOURCE_PRIVATE_KEY`. |
| `RESCUER_ARTIFACT` | `artifacts/contracts/RescuerV2.json` | Непустой путь к закреплённому canonical artifact. |
| `RPC_READ_TIMEOUT` | `10s` | Положительная длительность Go без окружающих пробелов и знака. |
| `STATE_DIRECTORY` | `state` | Непустой нормализованный путь без NUL; `filepath.Clean(value)` должен совпадать с исходным значением. |
| `WATCH_LOOKBACK_BLOCKS` | `64` | Положительное десятичное целое `uint64`, не больше `10000`. |
| `MAX_TRANSACTION_COST_WEI` | `10000000000000000` | Положительное десятичное целое `uint256`. Общий предел одной транзакции. |
| `HOURLY_BUDGET_WEI` | `20000000000000000` | Положительное десятичное целое `uint256`. Бюджет скользящего часа. |
| `DAILY_BUDGET_WEI` | `30000000000000000` | Положительное десятичное целое `uint256`. Бюджет скользящих суток. |
| `CUMULATIVE_BUDGET_WEI` | `50000000000000000` | Положительное десятичное целое `uint256`. Накопительный бюджет. |
| `SPONSOR_MIN_BALANCE_WEI` | `20000000000000000` | Положительное десятичное целое `uint256`. Общий неснижаемый резерв sponsor. |
| `RATE_LIMIT_PER_MINUTE` | `6` | Положительное десятичное целое `uint32`. Общая частота платных попыток. |
| `ABUSE_WINDOW` | `1h` | Положительная длительность Go без окружающих пробелов и знака. |
| `MAX_NEW_UNKNOWN_TOKENS_PER_WINDOW` | `16` | Положительное десятичное целое `uint32`. Новые адреса неизвестных токенов за `ABUSE_WINDOW`. |
| `MAX_ATTEMPTS_PER_TOKEN_WINDOW` | `3` | Положительное десятичное целое `uint32`. Попытки одного адреса токена за `ABUSE_WINDOW`. |
| `MAX_ATTEMPTS_PER_SOURCE_EVENT` | `3` | Положительное десятичное целое `uint32`. Попытки одного события source. |
| `ALERT_COOLDOWN` | `15m` | Положительная длительность Go без окружающих пробелов и знака. |

Три адреса ролей должны попарно различаться. Все wei-поля принимают только
десятичные цифры: знак, пробелы, дробь, шестнадцатеричная форма, переполнение и
ноль для положительного поля отклоняются. Общие бюджеты должны удовлетворять

```text
MAX_TRANSACTION_COST_WEI <= HOURLY_BUDGET_WEI <= DAILY_BUDGET_WEI <= CUMULATIVE_BUDGET_WEI
```

## Реестр сетей

`ENABLED_NETWORKS` принимает только имена из таблицы. Наличие записи означает
совместимость со схемой конфигурации, но не подтверждает поддержку EIP-7702,
наличие проверенного развёртывания или допуск платных операций.

| Имя | Chain ID | Суффикс полей |
|---|---:|---|
| `ethereum` | 1 | `ETHEREUM` |
| `optimism` | 10 | `OPTIMISM` |
| `bnb` | 56 | `BNB` |
| `polygon` | 137 | `POLYGON` |
| `metis` | 1088 | `METIS` |
| `base` | 8453 | `BASE` |
| `arbitrum` | 42161 | `ARBITRUM` |
| `ink` | 57073 | `INK` |
| `linea` | 59144 | `LINEA` |
| `scroll` | 534352 | `SCROLL` |

В репозитории нет официальных deployment manifests. Для каждой включённой сети
оператор обязан предоставить собственный доверенный `RESCUER_MANIFEST_<N>`.
Документация не заявляет готовность этих сетей к production.

## Поля сети

Для каждого имени из `ENABLED_NETWORKS` все шаблоны используют суффикс `<N>` в
верхнем регистре. Например, для `base` поле
`RPC_READ_1_HTTP_<N>` превращается в `RPC_READ_1_HTTP_BASE`.

| Шаблон | Значение по умолчанию | Требования |
|---|---|---|
| `RPC_READ_1_HTTP_<N>` | нет | Обязательный HTTP URL первого провайдера чтения. |
| `RPC_READ_1_WS_<N>` | нет | Обязательный WebSocket URL первого провайдера чтения. |
| `RPC_READ_1_TRUST_DOMAIN_<N>` | нет | Обязательный непустой домен доверия без окружающих пробелов. |
| `RPC_READ_2_HTTP_<N>` | нет | Обязательный HTTP URL второго провайдера чтения. |
| `RPC_READ_2_WS_<N>` | нет | Обязательный WebSocket URL второго провайдера чтения. |
| `RPC_READ_2_TRUST_DOMAIN_<N>` | нет | Обязательный непустой домен доверия без окружающих пробелов. |
| `RPC_BROADCAST_HTTP_<N>` | нет | Запрещён при `DRY_RUN=true`; обязателен при `DRY_RUN=false`, включая emergency. |
| `RESCUER_MANIFEST_<N>` | нет | Обязательный непустой путь к доверенному manifest этой сети. |
| `RESCUER_RELEASE_COMMIT_<N>` | нет | Необязательный полный commit из 40 шестнадцатеричных символов в нижнем регистре. Если задан, manifest обязан иметь `source.kind=git-commit` и это значение. |
| `TOKEN_MODE_<N>` | `known-only` | Одно из значений `known-only`, `allowlist`, `all`. |
| `TOKEN_ALLOWLIST_<N>` | нет | Обязательный и допустимый только при `TOKEN_MODE_<N>=allowlist`; непустой список уникальных ненулевых EVM-адресов. |
| `NETWORK_MAX_TRANSACTION_COST_WEI_<N>` | `8000000000000000` или меньший общий предел | Положительный `uint256`, не больше `MAX_TRANSACTION_COST_WEI`. |
| `NETWORK_HOURLY_BUDGET_WEI_<N>` | `15000000000000000` или меньший общий предел | Положительный `uint256`, не больше `HOURLY_BUDGET_WEI`. |
| `NETWORK_DAILY_BUDGET_WEI_<N>` | `25000000000000000` или меньший общий предел | Положительный `uint256`, не больше `DAILY_BUDGET_WEI`. |
| `NETWORK_CUMULATIVE_BUDGET_WEI_<N>` | `40000000000000000` или меньший общий предел | Положительный `uint256`, не больше `CUMULATIVE_BUDGET_WEI`. |
| `NETWORK_SPONSOR_MIN_BALANCE_WEI_<N>` | `20000000000000000` или больший общий резерв | Положительный `uint256`, не меньше `SPONSOR_MIN_BALANCE_WEI`. |
| `MAX_FEE_PER_GAS_WEI_<N>` | зависит от сети | Положительный `uint256`. |
| `MAX_PRIORITY_FEE_PER_GAS_WEI_<N>` | зависит от сети | Положительный `uint256`, не больше `MAX_FEE_PER_GAS_WEI_<N>`. |
| `TOKEN_GAS_LIMIT_<N>` | `300000` | Положительное десятичное целое `uint64`. |
| `TOKEN_VALUE_RULES_<N>` | нет | Необязательный список правил `address:minimum_raw_balance:max_cost_wei`. Для обычного live-запуска правило требуется для каждого trusted token. |
| `NATIVE_GAS_LIMIT_<N>` | `100000` | Положительное десятичное целое `uint64`. |
| `CHAIN_OVERHEAD_MAX_WEI_<N>` | зависит от сети | Неотрицательный десятичный `uint256`; это единственное wei-поле, допускающее ноль. |
| `NATIVE_MIN_NET_VALUE_WEI_<N>` | `1000000000000000` | Положительный `uint256`. |
| `UNKNOWN_TOKEN_MAX_TRANSACTION_COST_WEI_<N>` | `2000000000000000` или меньший сетевой предел | Положительный `uint256`, не больше `NETWORK_MAX_TRANSACTION_COST_WEI_<N>`. |

## RPC и политика транспорта

Парсер принимает для HTTP-полей схемы `http` и `https`, а для WebSocket-полей
схемы `ws` и `wss`; URL обязан содержать схему и host. Это позволяет использовать
`http`/`ws` на loopback при изолированной локальной проверке. Парсер не
ограничивает небезопасные схемы только loopback-адресами, поэтому для production
действует отдельная операторская политика: только `https` и `wss`.

Два провайдера чтения должны иметь разные канонические HTTP URL, разные
канонические WebSocket URL и разные без учёта регистра домены доверия. Broadcast
URL должен отличаться от обоих HTTP URL чтения. RPC отправки не участвует в
чтении и аттестации. Полные URL и их данные доступа не выводятся в ошибках или
журналах.

Минимальный набор сетевых полей для dry-run:

```dotenv
RPC_READ_1_HTTP_<N>=https://YOUR_READ_RPC_1
RPC_READ_1_WS_<N>=wss://YOUR_READ_RPC_1
RPC_READ_1_TRUST_DOMAIN_<N>=YOUR_INDEPENDENT_TRUST_DOMAIN_1
RPC_READ_2_HTTP_<N>=https://YOUR_READ_RPC_2
RPC_READ_2_WS_<N>=wss://YOUR_READ_RPC_2
RPC_READ_2_TRUST_DOMAIN_<N>=YOUR_INDEPENDENT_TRUST_DOMAIN_2
RESCUER_MANIFEST_<N>=PATH_TO_YOUR_TRUSTED_MANIFEST
# Для официального manifest выпуска:
RESCUER_RELEASE_COMMIT_<N>=FULL_40_LOWERCASE_HEX_MANIFEST_RELEASE_COMMIT
```

Без `RESCUER_RELEASE_COMMIT_<N>` ожидается legacy/development manifest с
закреплённым в коде `source.kind=source-tree-sha256` и digest canonical source
tree. Это безопасное значение по умолчанию не выводится из commit текущего
бинарного файла. Для официального manifest оператор обязан получить release
commit из проверенных метаданных неизменяемого кандидата выпуска и явно задать
его в поле соответствующей сети. При обновлении только бинарного файла с R1 на
R2 неизменённые manifest и `RESCUER_RELEASE_COMMIT_<N>` остаются на R1. Пустое,
сокращённое, содержащее заглавные символы или иным образом некорректное значение
останавливает загрузку конфигурации.

`RESCUER_ARTIFACT` всегда проверяется относительно закреплённого происхождения
canonical source tree. `RESCUER_RELEASE_COMMIT_<N>` меняет только ожидаемое поле
`source` deployment manifest и не переопределяет доверие к artifact.

При `DRY_RUN=false`, в том числе при `EMERGENCY_STOP=true`, дополнительно
требуется поле:

```dotenv
RPC_BROADCAST_HTTP_<N>=https://YOUR_SEPARATE_BROADCAST_RPC
```

Emergency сохраняет это требование схемы, но код не создаёт broadcaster и не
подключается к RPC отправки. Оба systemd credential обязаны быть пустыми;
непустое значение блокирует startup до создания signer. Новые подписи и отправки
запрещены. RPC чтения, manifests, аттестация, persistent state и наблюдение
остаются обязательными.

## Экономическая политика

Если общий бюджет явно уменьшен ниже сетевого значения по умолчанию, незаданное
сетевое значение автоматически уменьшается до общего предела. Если общий
`SPONSOR_MIN_BALANCE_WEI` увеличен, незаданный сетевой резерв автоматически
увеличивается до него. Явные сетевые значения обязаны соблюдать те же границы и
порядок:

```text
NETWORK_MAX_TRANSACTION_COST_WEI_<N>
  <= NETWORK_HOURLY_BUDGET_WEI_<N>
  <= NETWORK_DAILY_BUDGET_WEI_<N>
  <= NETWORK_CUMULATIVE_BUDGET_WEI_<N>
```

Сетевые значения fee и overhead по умолчанию:

| Сеть | `MAX_FEE_PER_GAS_WEI_<N>` | `MAX_PRIORITY_FEE_PER_GAS_WEI_<N>` | `CHAIN_OVERHEAD_MAX_WEI_<N>` | Допуск платных операций live |
|---|---:|---:|---:|---|
| `base` | `20000000000` | `2000000000` | `500000000000000` | Заблокировано: дополнительная комиссия не имеет transaction cap |
| `ethereum` | `25000000000` | `3000000000` | `0` | Допустимо по fee model |
| `arbitrum` | `3000000000` | `100000000` | `1100000000000000` | Заблокировано: дополнительная комиссия не имеет transaction cap |
| `optimism` | `4000000000` | `50000000` | `1200000000000000` | Заблокировано: дополнительная комиссия не имеет transaction cap |
| `polygon` | `25000000000` | `20000000000` | `0` | Допустимо по fee model |
| `ink` | `5000000000` | `100000000` | `700000000000000` | Заблокировано: дополнительная комиссия не имеет transaction cap |
| `scroll` | `5000000000` | `500000000` | `1500000000000000` | Заблокировано: дополнительная комиссия не имеет transaction cap |
| `linea` | `5000000000` | `500000000` | `1800000000000000` | Заблокировано: дополнительная комиссия не имеет transaction cap |
| `metis` | `10000000000` | `1000000000` | `800000000000000` | Заблокировано: дополнительная комиссия не имеет transaction cap |
| `bnb` | `10000000000` | `2000000000` | `0` | Допустимо по fee model |

Обе оценки должны помещаться в сетевой предел одной транзакции:

```text
TOKEN_GAS_LIMIT_<N> * MAX_FEE_PER_GAS_WEI_<N> + CHAIN_OVERHEAD_MAX_WEI_<N>
NATIVE_GAS_LIMIT_<N> * MAX_FEE_PER_GAS_WEI_<N> + CHAIN_OVERHEAD_MAX_WEI_<N>
```

`CHAIN_OVERHEAD_MAX_WEI_<N>` участвует в статической оценке, но не становится
ограничением комиссии протокола. Поэтому изменение этого поля не снимает
блокировку платных операций live для сети с некэпируемой дополнительной
комиссией. Допуск по модели комиссий также не означает готовность к production:
всё равно нужны доверенный manifest, аттестация и остальные проверки.

## Политика токенов

`TOKEN_MODE_<N>` управляет набором наблюдаемых контрактов:

| Значение | Поведение |
|---|---|
| `known-only` | Значение по умолчанию. Разрешены только известные системе токены. |
| `allowlist` | Разрешены только адреса из обязательного `TOKEN_ALLOWLIST_<N>`. |
| `all` | Явно разрешает неизвестные контракты токенов; при запуске демон выдаёт предупреждение оператору. |

Allowlisted unknown address остаётся разрешённым для watcher, но не получает
известные metadata или доверенную оценку ценности. Платная попытка для него
дополнительно ограничена `UNKNOWN_TOKEN_MAX_TRANSACTION_COST_WEI_<N>` как в
`allowlist`, так и в `all`.

`TOKEN_VALUE_RULES_<N>` содержит разделённые запятыми правила:

```dotenv
TOKEN_VALUE_RULES_<N>=0xTOKEN:1000000:1000000000000000
```

Адрес должен быть ненулевым, уникальным и входить в trusted tokens выбранного
режима. Оба числа должны быть положительными десятичными `uint256`, а
`max_cost_wei` не может превышать `NETWORK_MAX_TRANSACTION_COST_WEI_<N>`. В
обычном live-режиме отсутствие правила хотя бы для одного trusted token
блокирует создание coordinator до первой подписи. При emergency gate уже
остановлен, поэтому правила могут отсутствовать.

Правило определяет только допуск по минимальному raw balance и максимальной
стоимости попытки. Для любого ERC-20 итог всегда имеет статус `token-reported`:
receipt, `balanceOf`, return data и `Transfer` не доказывают экономическую
ценность.

## Режимы и запуск

### Dry-run

`DRY_RUN=true` или отсутствие поля запрещает `RPC_BROADCAST_HTTP_<N>`. Оба
systemd credential обязаны быть пустыми; непустое значение блокирует startup.
Рабочие signers и broadcaster не создаются, подписи и отправка не выполняются.
Демон загружает публичную конфигурацию и manifests, открывает локальное
состояние, подключается к RPC чтения, наблюдает события и выполняет планирование
с `EstimateGas`.

### Live

`DRY_RUN=false` и `EMERGENCY_STOP=false` требуют оба private key только из
systemd credentials `source-private-key` и `sponsor-private-key`, а также
отдельный `RPC_BROADCAST_HTTP_<N>` для каждой сети. Сначала загружаются все
manifests, затем все сети проходят аттестацию двумя независимыми RPC на
согласованном финализированном блоке. После открытия состояния, budget и leases
создаются signers, а их адреса сверяются с `SOURCE_ADDRESS` и `SPONSOR_ADDRESS`
до первой подписи. Любое расхождение останавливает запуск.
Наличие объекта любого типа по фиксированному операторскому пути
`/var/lib/guard-daemon-operator/live-disabled-after-restore` также останавливает
live startup до создания signer. Путь не является runtime-настройкой и не
зависит от `STATE_DIRECTORY`. Ошибка `lstat` marker, кроме подтверждённого
отсутствия, обрабатывается fail-closed.

### Emergency

`DRY_RUN=false` и `EMERGENCY_STOP=true` сохраняют live-проверку конфигурации:
`RPC_BROADCAST_HTTP_<N>`, manifests, RPC чтения и аттестация обязательны. При
этом оба systemd credential обязаны быть пустыми, signers и broadcaster не
создаются. Новые подписи и отправки запрещены; watcher, финализированные чтения,
согласование receipts и diagnostics продолжают работу.
Этот режим допускается при внешнем marker
`/var/lib/guard-daemon-operator/live-disabled-after-restore` только для
наблюдения. Dry-run имеет тот же допуск без возможности signing.

## Состояние и восстановление

При первом запуске без checkpoint демон сканирует ограниченное окно ретроспективного просмотра до согласованного финализированного блока. Размер задаёт `WATCH_LOOKBACK_BLOCKS`.

Локальное состояние обязательно для восстановления после сбоя. Для каждой сети
в `STATE_DIRECTORY` создаётся отдельная база watcher. Повреждение state, несовпадение сохранённой идентичности сети или конфигурации и невозможность получить эксклюзивную блокировку являются fail-closed ошибками запуска. Пустой существующий файл также не переинициализируется автоматически.

Checkpoint продвигается только после durable `Ack` соответствующих candidates.
После сбоя неподтверждённая работа воспроизводится. Во время работы в
`STATE_DIRECTORY` создаётся Unix socket `diagnostics.sock` с правами `0600`; при
штатной остановке он удаляется.

Привязанные к sponsor budget, admission counters и alerts хранятся отдельно в
`/var/lib/guard-daemon`. Каталог должен быть durable, принадлежать пользователю
daemon и иметь режим `0700`. Потеря этих данных не является допустимым способом
сбросить лимиты.

Процедура восстановления до изменения state создаёт root-owned marker
`/var/lib/guard-daemon-operator/live-disabled-after-restore`. Его родитель имеет
режим `0755`, не доступен daemon для записи и не входит в архив
`/var/lib/guard-daemon`. В этом выпуске marker не удаляется: восстановленное
дерево разрешено открывать только в dry-run или emergency для наблюдения и
расследования и никогда нельзя возвращать в signing.

## Удалённые поля

Прежние адреса `RESCUER_*`, старые `RPC_URL_*`, `RESCUE_TOKENS`,
`TOKENS_TO_SWEEP`, `CLAIM_*`, `SPONSOR_MIN_BALANCE` и `RESCUER_MODE` не
поддерживаются. Это не относится к актуальным `RESCUER_ARTIFACT` и
`RESCUER_MANIFEST_<N>`. Наличие удалённого или неизвестного зарезервированного
поля останавливает загрузку конфигурации.
