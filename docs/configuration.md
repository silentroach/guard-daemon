# Конфигурация guard-daemon

Это полный справочник поддерживаемых переменных окружения. Конфигурация
проверяется при запуске; отдельной команды для её проверки нет. Пример
[`.env.example`](../.env.example) намеренно содержит заглушки и не готов к
запуску.

## Источники значений

Необязательный файл `.env` читается из текущего рабочего каталога. Файл службы
systemd задаёт `GUARD_DAEMON_CONFIG=/etc/guard-daemon/guard-daemon.env`, поэтому
служба читает публичную конфигурацию по этому фиксированному пути после запрета
дампов памяти. Допустимы только строки `NAME=value`, пустые строки и комментарии.
Формы `NAME: value` и `export NAME=value` отклоняются до разбора значений. Если
поле задано и в окружении процесса, и в `.env`, значение из окружения процесса
имеет приоритет.

`SOURCE_PRIVATE_KEY` и `SPONSOR_PRIVATE_KEY` являются исключением: строки с
этими именами пропускаются при чтении `.env`, а одноимённые переменные начального
окружения процесса запрещены. Поддерживаемая служба systemd передаёт значения
через `LoadCredential` из `/etc/guard-daemon/credentials/source-private-key` и
`/etc/guard-daemon/credentials/sponsor-private-key`. Программа читает файлы
учётных данных только после `RLIMIT_CORE=0` и `PR_SET_DUMPABLE=0`. В режимах
dry-run и аварийной остановки их значения не разбираются и не сохраняются в
конфигурации.

Неизвестные имена в зарезервированных пространствах имён `RPC_*`, `RESCUER_*`,
`TOKEN_*`, `NETWORK_*`, `SPONSOR_*`, `STATE_*` и других пространствах имён схемы
вызывают ошибку. Ошибка называет поле, но не выводит его значение.

## Общие поля

| Поле | Значение по умолчанию | Требования |
|---|---|---|
| `DRY_RUN` | `true` | Только `true` или `false`. Значение `false` выбирает рабочий режим. |
| `EMERGENCY_STOP` | `false` | Только `true` или `false`. Действует совместно с `DRY_RUN=false`. |
| `SOURCE_ADDRESS` | нет | Обязательный ненулевой адрес EVM наблюдаемой роли `source`. |
| `SPONSOR_ADDRESS` | нет | Обязательный ненулевой адрес EVM роли `sponsor`, оплачивающей комиссии. |
| `DESTINATION_ADDRESS` | нет | Обязательный ненулевой адрес EVM безопасной роли `destination`. |
| `ENABLED_NETWORKS` | нет | Обязательный непустой список имён сетей через запятую. Имена должны быть известными, неповторяющимися и записанными в нижнем регистре. |
| `SOURCE_PRIVATE_KEY` | нет | В рабочем режиме без аварийной остановки обязателен и должен передаваться через `LoadCredential` systemd под именем `source-private-key`. Допустимый приватный ключ secp256k1: 64 шестнадцатеричные цифры и необязательный префикс `0x`. |
| `SPONSOR_PRIVATE_KEY` | нет | В рабочем режиме без аварийной остановки обязателен и должен передаваться через `LoadCredential` systemd под именем `sponsor-private-key`. Формат совпадает с `SOURCE_PRIVATE_KEY`. |
| `RESCUER_ARTIFACT` | `artifacts/contracts/RescuerV2.json` | Непустой путь к закреплённому каноническому артефакту. |
| `RPC_READ_TIMEOUT` | `10s` | Положительное значение длительности в формате Go без пробелов в начале и конце и без знака. |
| `STATE_DIRECTORY` | `state` | Непустой нормализованный путь без NUL; `filepath.Clean(value)` должен совпадать с исходным значением. |
| `WATCH_LOOKBACK_BLOCKS` | `64` | Положительное десятичное целое `uint64`, не больше `10000`. |
| `MAX_TRANSACTION_COST_WEI` | `10000000000000000` | Положительное десятичное целое `uint256`. Общий предел одной транзакции. |
| `HOURLY_BUDGET_WEI` | `20000000000000000` | Положительное десятичное целое `uint256`. Бюджет скользящего часа. |
| `DAILY_BUDGET_WEI` | `30000000000000000` | Положительное десятичное целое `uint256`. Бюджет скользящих суток. |
| `CUMULATIVE_BUDGET_WEI` | `50000000000000000` | Положительное десятичное целое `uint256`. Накопительный бюджет. |
| `SPONSOR_MIN_BALANCE_WEI` | `20000000000000000` | Положительное десятичное целое `uint256`. Общий неснижаемый резерв `sponsor`. |
| `RATE_LIMIT_PER_MINUTE` | `6` | Положительное десятичное целое `uint32`. Общая частота платных попыток. |
| `ABUSE_WINDOW` | `1h` | Положительное значение длительности в формате Go без пробелов в начале и конце и без знака. |
| `MAX_NEW_UNKNOWN_TOKENS_PER_WINDOW` | `16` | Положительное десятичное целое `uint32`. Новые адреса неизвестных токенов за `ABUSE_WINDOW`. |
| `MAX_ATTEMPTS_PER_TOKEN_WINDOW` | `3` | Положительное десятичное целое `uint32`. Попытки одного адреса токена за `ABUSE_WINDOW`. |
| `MAX_ATTEMPTS_PER_SOURCE_EVENT` | `3` | Положительное десятичное целое `uint32`. Попытки для одного события `source`. |
| `ALERT_COOLDOWN` | `15m` | Положительное значение длительности в формате Go без пробелов в начале и конце и без знака. |

Три адреса ролей должны попарно различаться. Все поля в wei принимают только
десятичные цифры: знак, пробелы, дробь, шестнадцатеричная форма, переполнение и
ноль для положительного поля отклоняются. Общие бюджеты должны удовлетворять

```text
MAX_TRANSACTION_COST_WEI <= HOURLY_BUDGET_WEI <= DAILY_BUDGET_WEI <= CUMULATIVE_BUDGET_WEI
```

## Реестр сетей

`ENABLED_NETWORKS` принимает только имена из таблицы. Наличие записи означает
совместимость со схемой конфигурации, но не подтверждает поддержку EIP-7702,
наличие проверенного развёртывания или допуск платных операций.

| Имя | Идентификатор сети | Суффикс полей |
|---|---:|---|
| `ethereum` | 1 | `ETHEREUM` |
| `optimism` | 10 | `OPTIMISM` |
| `bnb` | 56 | `BNB` |
| `polygon` | 137 | `POLYGON` |
| `metis` | 1088 | `METIS` |
| `base` | 8453 | `BASE` |
| `arbitrum` | 42161 | `ARBITRUM` |
| `ink` | 57073 | `INK` |
| `linea` | 59144 | `LINEA` |
| `scroll` | 534352 | `SCROLL` |

В репозитории нет официальных манифестов развёртывания. Для каждой включённой
сети оператор обязан предоставить собственный доверенный
`RESCUER_MANIFEST_<N>`.
Документация не заявляет о готовности этих сетей к промышленной эксплуатации.

## Поля сети

Для каждого имени из `ENABLED_NETWORKS` все шаблоны используют суффикс `<N>` в
верхнем регистре. Например, для `base` поле
`RPC_READ_1_HTTP_<N>` превращается в `RPC_READ_1_HTTP_BASE`.

| Шаблон | Значение по умолчанию | Требования |
|---|---|---|
| `RPC_READ_1_HTTP_<N>` | нет | Обязательный HTTP URL первого поставщика RPC для чтения. |
| `RPC_READ_1_WS_<N>` | нет | Обязательный WebSocket URL первого поставщика RPC для чтения. |
| `RPC_READ_1_TRUST_DOMAIN_<N>` | нет | Обязательный непустой домен доверия без окружающих пробелов. |
| `RPC_READ_2_HTTP_<N>` | нет | Обязательный HTTP URL второго поставщика RPC для чтения. |
| `RPC_READ_2_WS_<N>` | нет | Обязательный WebSocket URL второго поставщика RPC для чтения. |
| `RPC_READ_2_TRUST_DOMAIN_<N>` | нет | Обязательный непустой домен доверия без окружающих пробелов. |
| `RPC_BROADCAST_HTTP_<N>` | нет | Запрещён при `DRY_RUN=true`; обязателен при `DRY_RUN=false`, включая аварийный режим. |
| `RESCUER_MANIFEST_<N>` | нет | Обязательный непустой путь к доверенному манифесту этой сети. |
| `RESCUER_RELEASE_COMMIT_<N>` | нет | Необязательный полный идентификатор коммита из 40 шестнадцатеричных символов в нижнем регистре. Если поле задано, манифест обязан содержать `source.kind=git-commit` и указанное значение. |
| `TOKEN_MODE_<N>` | `known-only` | Одно из значений `known-only`, `allowlist`, `all`. |
| `TOKEN_ALLOWLIST_<N>` | нет | Обязательный и допустимый только при `TOKEN_MODE_<N>=allowlist`; непустой список уникальных ненулевых адресов EVM. |
| `NETWORK_MAX_TRANSACTION_COST_WEI_<N>` | `8000000000000000` или меньший общий предел | Положительный `uint256`, не больше `MAX_TRANSACTION_COST_WEI`. |
| `NETWORK_HOURLY_BUDGET_WEI_<N>` | `15000000000000000` или меньший общий предел | Положительный `uint256`, не больше `HOURLY_BUDGET_WEI`. |
| `NETWORK_DAILY_BUDGET_WEI_<N>` | `25000000000000000` или меньший общий предел | Положительный `uint256`, не больше `DAILY_BUDGET_WEI`. |
| `NETWORK_CUMULATIVE_BUDGET_WEI_<N>` | `40000000000000000` или меньший общий предел | Положительный `uint256`, не больше `CUMULATIVE_BUDGET_WEI`. |
| `NETWORK_SPONSOR_MIN_BALANCE_WEI_<N>` | `20000000000000000` или больший общий резерв | Положительный `uint256`, не меньше `SPONSOR_MIN_BALANCE_WEI`. |
| `MAX_FEE_PER_GAS_WEI_<N>` | зависит от сети | Положительный `uint256`. |
| `MAX_PRIORITY_FEE_PER_GAS_WEI_<N>` | зависит от сети | Положительный `uint256`, не больше `MAX_FEE_PER_GAS_WEI_<N>`. |
| `TOKEN_GAS_LIMIT_<N>` | `300000` | Положительное десятичное целое `uint64`. |
| `TOKEN_VALUE_RULES_<N>` | нет | Необязательный список правил `address:minimum_raw_balance:max_cost_wei`. Для обычного запуска в рабочем режиме правило требуется для каждого доверенного токена. |
| `NATIVE_GAS_LIMIT_<N>` | `100000` | Положительное десятичное целое `uint64`. |
| `CHAIN_OVERHEAD_MAX_WEI_<N>` | зависит от сети | Неотрицательный десятичный `uint256`; это единственное поле в wei, допускающее ноль. |
| `NATIVE_MIN_NET_VALUE_WEI_<N>` | `1000000000000000` | Положительный `uint256`. |
| `UNKNOWN_TOKEN_MAX_TRANSACTION_COST_WEI_<N>` | `2000000000000000` или меньший сетевой предел | Положительный `uint256`, не больше `NETWORK_MAX_TRANSACTION_COST_WEI_<N>`. |

## RPC и политика транспорта

Парсер принимает для HTTP-полей схемы `http` и `https`, а для WebSocket-полей
схемы `ws` и `wss`; URL обязан содержать схему и имя узла. Это позволяет
использовать `http` и `ws` через интерфейс обратной петли при изолированной
локальной проверке. Парсер не проверяет, что небезопасные схемы используются
только с адресами обратной петли, поэтому в промышленной среде действует
отдельное правило оператора: только `https` и `wss`.

Два поставщика RPC для чтения должны иметь разные канонические HTTP URL, разные
канонические WebSocket URL и разные без учёта регистра домены доверия. URL RPC
для отправки должен отличаться от обоих HTTP URL для чтения. RPC для отправки не
участвует в чтении и аттестации. Полные URL и их данные доступа не выводятся в
ошибках или журналах.

Минимальный набор сетевых полей для dry-run:

```dotenv
RPC_READ_1_HTTP_<N>=https://YOUR_READ_RPC_1
RPC_READ_1_WS_<N>=wss://YOUR_READ_RPC_1
RPC_READ_1_TRUST_DOMAIN_<N>=YOUR_INDEPENDENT_TRUST_DOMAIN_1
RPC_READ_2_HTTP_<N>=https://YOUR_READ_RPC_2
RPC_READ_2_WS_<N>=wss://YOUR_READ_RPC_2
RPC_READ_2_TRUST_DOMAIN_<N>=YOUR_INDEPENDENT_TRUST_DOMAIN_2
RESCUER_MANIFEST_<N>=PATH_TO_YOUR_TRUSTED_MANIFEST
# Для официального манифеста выпуска:
RESCUER_RELEASE_COMMIT_<N>=FULL_40_LOWERCASE_HEX_MANIFEST_RELEASE_COMMIT
```

Без `RESCUER_RELEASE_COMMIT_<N>` ожидается манифест старого формата или манифест
для разработки с закреплённым в коде `source.kind=source-tree-sha256` и хешем
канонического дерева исходников. Это безопасное значение по умолчанию не
выводится из коммита текущего бинарного файла. Для официального манифеста
оператор обязан получить коммит выпуска из проверенных метаданных неизменяемого
кандидата выпуска и явно задать его в поле соответствующей сети. При обновлении
только бинарного файла с R1 на R2 неизменённые манифест и
`RESCUER_RELEASE_COMMIT_<N>` остаются на R1. Пустое,
сокращённое, содержащее заглавные символы или иным образом некорректное значение
останавливает загрузку конфигурации.

`RESCUER_ARTIFACT` всегда проверяется относительно закреплённого происхождения
канонического дерева исходников. `RESCUER_RELEASE_COMMIT_<N>` меняет только
ожидаемое поле `source` манифеста развёртывания и не переопределяет доверие к
артефакту.

При `DRY_RUN=false`, в том числе при `EMERGENCY_STOP=true`, дополнительно
требуется поле:

```dotenv
RPC_BROADCAST_HTTP_<N>=https://YOUR_SEPARATE_BROADCAST_RPC
```

В аварийном режиме это требование схемы сохраняется, но программа не создаёт
компонент отправки и не подключается к RPC для отправки. Оба значения,
передаваемые systemd через `LoadCredential`, обязаны быть пустыми; непустое
значение блокирует запуск до создания средства подписи. Новые подписи и отправки
запрещены. RPC для чтения, манифесты, аттестация, постоянное состояние и
наблюдение остаются обязательными.

## Экономическая политика

Если общий бюджет явно уменьшен ниже сетевого значения по умолчанию, незаданное
сетевое значение автоматически уменьшается до общего предела. Если общий
`SPONSOR_MIN_BALANCE_WEI` увеличен, незаданный сетевой резерв автоматически
увеличивается до него. Явные сетевые значения обязаны соблюдать те же границы и
порядок:

```text
NETWORK_MAX_TRANSACTION_COST_WEI_<N>
  <= NETWORK_HOURLY_BUDGET_WEI_<N>
  <= NETWORK_DAILY_BUDGET_WEI_<N>
  <= NETWORK_CUMULATIVE_BUDGET_WEI_<N>
```

Сетевые значения комиссии и дополнительных расходов по умолчанию:

| Сеть | `MAX_FEE_PER_GAS_WEI_<N>` | `MAX_PRIORITY_FEE_PER_GAS_WEI_<N>` | `CHAIN_OVERHEAD_MAX_WEI_<N>` | Допуск платных операций в рабочем режиме |
|---|---:|---:|---:|---|
| `base` | `20000000000` | `2000000000` | `500000000000000` | Заблокировано: дополнительная комиссия не ограничивается на уровне транзакции |
| `ethereum` | `25000000000` | `3000000000` | `0` | Допустимо по модели комиссий |
| `arbitrum` | `3000000000` | `100000000` | `1100000000000000` | Заблокировано: дополнительная комиссия не ограничивается на уровне транзакции |
| `optimism` | `4000000000` | `50000000` | `1200000000000000` | Заблокировано: дополнительная комиссия не ограничивается на уровне транзакции |
| `polygon` | `25000000000` | `20000000000` | `0` | Допустимо по модели комиссий |
| `ink` | `5000000000` | `100000000` | `700000000000000` | Заблокировано: дополнительная комиссия не ограничивается на уровне транзакции |
| `scroll` | `5000000000` | `500000000` | `1500000000000000` | Заблокировано: дополнительная комиссия не ограничивается на уровне транзакции |
| `linea` | `5000000000` | `500000000` | `1800000000000000` | Заблокировано: дополнительная комиссия не ограничивается на уровне транзакции |
| `metis` | `10000000000` | `1000000000` | `800000000000000` | Заблокировано: дополнительная комиссия не ограничивается на уровне транзакции |
| `bnb` | `10000000000` | `2000000000` | `0` | Допустимо по модели комиссий |

Обе оценки должны помещаться в сетевой предел одной транзакции:

```text
TOKEN_GAS_LIMIT_<N> * MAX_FEE_PER_GAS_WEI_<N> + CHAIN_OVERHEAD_MAX_WEI_<N>
NATIVE_GAS_LIMIT_<N> * MAX_FEE_PER_GAS_WEI_<N> + CHAIN_OVERHEAD_MAX_WEI_<N>
```

`CHAIN_OVERHEAD_MAX_WEI_<N>` участвует в статической оценке, но не становится
ограничением комиссии протокола. Поэтому изменение этого поля не снимает
блокировку платных операций в рабочем режиме для сети, где дополнительную
комиссию нельзя ограничить. Допуск по модели комиссий также не означает
готовности к промышленной эксплуатации: всё равно нужны доверенный манифест,
аттестация и остальные проверки.

## Политика токенов

`TOKEN_MODE_<N>` управляет набором наблюдаемых контрактов:

| Значение | Поведение |
|---|---|
| `known-only` | Значение по умолчанию. Разрешены только известные системе токены. |
| `allowlist` | Разрешены только адреса из обязательного `TOKEN_ALLOWLIST_<N>`. |
| `all` | Явно разрешает неизвестные контракты токенов; при запуске демон выдаёт предупреждение оператору. |

Неизвестный адрес из списка разрешённых остаётся доступным компоненту
наблюдения, но не получает известных метаданных или доверенной оценки ценности.
Платная попытка для него дополнительно ограничена
`UNKNOWN_TOKEN_MAX_TRANSACTION_COST_WEI_<N>` как в режиме `allowlist`, так и в
режиме `all`.

`TOKEN_VALUE_RULES_<N>` содержит разделённые запятыми правила:

```dotenv
TOKEN_VALUE_RULES_<N>=0xTOKEN:1000000:1000000000000000
```

Адрес должен быть ненулевым, уникальным и входить в доверенные токены выбранного
режима. Оба числа должны быть положительными десятичными `uint256`, а
`max_cost_wei` не может превышать `NETWORK_MAX_TRANSACTION_COST_WEI_<N>`. В
обычном рабочем режиме отсутствие правила хотя бы для одного доверенного токена
блокирует создание координатора до первой подписи. В аварийном режиме подпись
уже запрещена, поэтому правила могут отсутствовать.

Правило определяет только допуск по минимальному исходному балансу и максимальной
стоимости попытки. Для любого ERC-20 итог всегда имеет статус `token-reported`:
квитанция транзакции, `balanceOf`, возвращённые данные и `Transfer` не доказывают
экономическую ценность.

## Режимы и запуск

### Dry-run

`DRY_RUN=true` или отсутствие поля запрещает `RPC_BROADCAST_HTTP_<N>`. Оба
значения, передаваемые systemd через `LoadCredential`, обязаны быть пустыми;
непустое значение блокирует запуск. Средства подписи и компонент отправки для
рабочего режима не создаются, подписи и отправка не выполняются. Демон загружает
публичную конфигурацию и манифесты, открывает локальное состояние, подключается к
RPC для чтения, наблюдает события и выполняет планирование с `EstimateGas`.

### Рабочий режим

`DRY_RUN=false` и `EMERGENCY_STOP=false` требуют оба приватных ключа только из
учётных данных systemd `source-private-key` и `sponsor-private-key`, а также
отдельный `RPC_BROADCAST_HTTP_<N>` для каждой сети. Сначала загружаются все
манифесты, затем все сети проходят аттестацию через двух независимых поставщиков
RPC на согласованном финализированном блоке. После открытия состояния, бюджета и
аренд создаются средства подписи, а их адреса сверяются с `SOURCE_ADDRESS` и
`SPONSOR_ADDRESS` до первой подписи. Любое расхождение останавливает запуск.
Наличие объекта любого типа по фиксированному операторскому пути
`/var/lib/guard-daemon-operator/live-disabled-after-restore` также останавливает
запуск в рабочем режиме до создания средства подписи. Путь не является
настройкой времени выполнения и не зависит от `STATE_DIRECTORY`. Любая ошибка
`lstat`, кроме подтверждённого отсутствия маркера, останавливает запуск.

### Аварийный режим

`DRY_RUN=false` и `EMERGENCY_STOP=true` сохраняют проверку конфигурации рабочего
режима: `RPC_BROADCAST_HTTP_<N>`, манифесты, RPC для чтения и аттестация
обязательны.
При этом оба значения, передаваемые systemd через `LoadCredential`, обязаны быть
пустыми, а средства подписи и компонент отправки не создаются. Новые подписи и
отправки запрещены; компонент наблюдения, финализированные чтения, согласование
квитанций транзакций и диагностика продолжают работу.
Этот режим допускается при наличии внешнего маркера
`/var/lib/guard-daemon-operator/live-disabled-after-restore` только для
наблюдения. Dry-run допускается при тех же условиях и не позволяет подписывать
транзакции.

## Состояние и восстановление

При первом запуске без контрольной точки демон сканирует ограниченное число предыдущих блоков до согласованного финализированного блока.
Размер окна задаёт `WATCH_LOOKBACK_BLOCKS`.

Локальное состояние обязательно для восстановления после сбоя. Для каждой сети
в `STATE_DIRECTORY` создаётся отдельная база компонента наблюдения.
Повреждение состояния, несовпадение сохранённого идентификатора сети или конфигурации и невозможность получить исключительную блокировку приводят к ошибке запуска.
Существующий пустой файл также не
переинициализируется автоматически.

Контрольная точка продвигается только после надёжной записи `Ack` для соответствующих кандидатов.
После сбоя неподтверждённая работа выполняется
повторно. Во время работы в `STATE_DIRECTORY` создаётся Unix-сокет
`diagnostics.sock` с правами `0600`; при штатной остановке он удаляется.

Бюджет, счётчики допуска и оповещения, привязанные к `sponsor`, хранятся отдельно
в `/var/lib/guard-daemon`. Каталог должен находиться на надёжном постоянном
хранилище, принадлежать пользователю службы и иметь режим `0700`. Потеря этих
данных не является допустимым способом сбросить лимиты.

Перед изменением состояния процедура восстановления создаёт принадлежащий
пользователю `root` маркер
`/var/lib/guard-daemon-operator/live-disabled-after-restore`. Его родитель имеет
режим `0755`, недоступен службе для записи и не входит в архив
`/var/lib/guard-daemon`. В этом выпуске маркер не удаляется: восстановленное
дерево разрешено открывать только в режимах dry-run или аварийной остановки для
наблюдения и расследования. Использовать его для подписи транзакций нельзя.

## Удалённые поля

Прежние адреса `RESCUER_*`, старые `RPC_URL_*`, `RESCUE_TOKENS`,
`TOKENS_TO_SWEEP`, `CLAIM_*`, `SPONSOR_MIN_BALANCE` и `RESCUER_MODE` не
поддерживаются. Это не относится к актуальным `RESCUER_ARTIFACT` и
`RESCUER_MANIFEST_<N>`. Наличие удалённого или неизвестного зарезервированного
поля останавливает загрузку конфигурации.
