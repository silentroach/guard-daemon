# Контрольный список кандидата выпуска

Этот список заполняется для одного полного `RELEASE_COMMIT`. Отметка пункта
означает наличие проверяемого подтверждения, а не только устное заверение.
До завершения задачи 11 кандидат нельзя публиковать.

## Коммит и независимая проверка

- [ ] `RELEASE_COMMIT` состоит ровно из 40 шестнадцатеричных символов в нижнем
      регистре и соответствует объекту коммита.
- [ ] Задачи 01-10 имеют статус `DONE` для выбранного коммита.
- [ ] Прочитаны отчёты независимой проверки задач 01-10; отчёт задачи 10 входит в
      коммит выпуска.
- [ ] В отчётах задач, матрице замечаний и реестре остаточных рисков нет открытых
      замечаний критического (`Critical`) или высокого (`High`) уровня.
- [ ] Все замечания среднего (`Medium`) и низкого (`Low`) уровня исправлены либо
      имеют явного владельца, обоснование и срок пересмотра.
- [ ] Рабочее дерево не используется как источник кандидата; сборка читает
      только снимок `RELEASE_COMMIT`.

## Полный CI

- [ ] На точном коммите успешно выполнены `npm ci` и
      `make security-validation` с версиями из
      [../development/ci.md](../development/ci.md).
- [ ] После выполнения требований к эксплуатации успешно выполнены
      `make documentation-check`, `make operations-check` и
      `make operations-rehearsal`.
- [ ] Репетиция использовала только одноразовый Anvil и локальные тестовые ключи;
      подпись и отправка были ограничены локальной цепочкой, а рабочие RPC,
      рабочие секретные данные и основная сеть не использовались.
- [ ] Все обязательные проверки GitHub для коммита завершились успешно.
- [ ] Оператор проверил через GitHub API фактическую защиту ветки или набор
      правил, запрет `force-push`, обязательную независимую проверку и
      обязательные проверки.
- [ ] Оператор проверил включение Dependabot и подтверждение его работы.
- [ ] Операторское подтверждение без закрытых данных соответствует
      [evidence/README.md](evidence/README.md); исходные ответы API, URL, токены,
      имена и идентификаторы учётных записей не добавлены.

Отсутствие любого внешнего операторского подтверждения блокирует выпуск. Этот
репозиторий не утверждает, что настройки GitHub уже включены.

## Сборка кандидата

- [ ] Команда выполнена с явно указанным полным коммитом:

```sh
make release-candidate RELEASE_COMMIT=<40hex>
```

- [ ] Создан только игнорируемый каталог `dist/release/<commit>/`.
- [ ] Целевая платформа равна `linux/amd64`, `CGO_ENABLED=0`.
- [ ] Каталог содержит ровно обязательные файлы из
      [artifacts.md](artifacts.md).
- [ ] `guard-daemon-source.tar` побайтово равен выводу `git archive` с
      каноническим префиксом `guard-daemon-<commit>/`.
- [ ] `RescuerV2.json`, `rescuer-manifest.schema.json` и `LICENSE` побайтово
      взяты из выбранного коммита.
- [ ] `guard-daemon.cdx.json` является корректным документом CycloneDX 1.6 JSON и
      содержит зависимости из закреплённых исходных данных Go и npm.
- [ ] `guard-daemon.intoto.jsonl` содержит один корректный неподписанный документ
      `in-toto Statement` со сведениями SLSA Provenance v1.
- [ ] Метаданные JSON не содержат меток времени, имён узла и пользователя,
      рабочего каталога, значений окружения, URL удалённых репозиториев или
      данных инцидента.
- [ ] `SHA256SUMS` перечисляет все остальные файлы и успешно проверяется.

## Две чистые сборки

- [ ] Один коммит собран в двух новых независимых копиях репозитория без локальных
      сгенерированных файлов и без использования Nix как обязательного условия.
- [ ] В каждой копии установлены те же точные версии инструментов и выполнен
      один и тот же `make release-candidate RELEASE_COMMIT=<40hex>`.
- [ ] Списки путей двух каталогов совпадают.
- [ ] `SHA256SUMS` двух сборок совпадают побайтово.
- [ ] Каждый файл, включая двоичный файл, архив исходного кода, SBOM, метаданные
      выпуска и сведения о происхождении, совпадает побайтово.
- [ ] Результат сравнения сохранён как подтверждение без закрытых данных,
      локальных путей, имён пользователей и URL репозитория.

Различие нельзя объяснять временем или машиной сборки: такие исходные данные запрещены.
При различии кандидат отклоняется, а исправление вносится в новый коммит.

## Секреты и содержимое

- [ ] Выполнен поиск секретов в исходном коде и полной истории Git командой
      `make secret-scan`.
- [ ] Отдельный поиск секретов прошёл по каждому каталогу
      `dist/release/<commit>/`, включая строки двоичного файла, JSONL, SBOM и tar.
- [ ] В сгенерированном результате нет закрытых ключей, мнемонических фраз,
      токенов, данных доступа, закрытых URL RPC, операторских адресов,
      персональных данных и локальных путей.
- [ ] `guard-daemon-source.tar` содержит русскоязычные руководства по выпуску,
      эксплуатации и развёртыванию, файлы фиксации версий зависимостей и отчёты
      независимой проверки задач 01-10.
- [ ] Кандидат не содержит официальный манифест развёртывания, секрет подписи,
      подпись или рабочую конфигурацию.

## Условия публикации

- [ ] Кандидат передан независимому проверяющему по задаче 11 только локально
      или через утверждённый оператором закрытый канал без секретных данных.
- [ ] До решения по задаче 11 не создавался тег, выпуск не публиковался, а
      артефакты не распространялись публично.
- [ ] Сценарии выпуска не выполняли `push`, не изменяли удалённые репозитории и
      не создавали GitHub Release.
- [ ] Агент не развёртывал контракт в основной сети, не отправлял транзакции, не
      пополнял счета и не выполнял подпись.
- [ ] Учтено, что контрольные суммы подтверждают целостность только относительно
      полученного списка и не подтверждают подлинность издателя.

После заполнения этого списка статус остаётся `КАНДИДАТ, ПУБЛИКАЦИЯ
ЗАБЛОКИРОВАНА`. Разрешение возможно только по итоговому отчёту задачи 11 со
словами `РАЗРЕШИТЬ ВЫПУСК`. Подпись и публикация после такого решения остаются
отдельными операторскими процедурами.
