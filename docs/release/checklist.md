# Контрольный список кандидата выпуска

Этот список заполняется для одного полного `RELEASE_COMMIT`. Отметка пункта
означает наличие проверяемого доказательства, а не только устное подтверждение.
До завершения Task 11 кандидат нельзя публиковать.

## Коммит и ревью

- [ ] `RELEASE_COMMIT` состоит ровно из 40 шестнадцатеричных символов в нижнем
      регистре и разрешается в commit object.
- [ ] Tasks 01-10 имеют статус `DONE` на выбранном commit.
- [ ] Прочитаны отчёты независимого ревью Tasks 01-10; отчёт Task 10 входит в
      release commit.
- [ ] В отчётах задач, матрице findings и реестре остаточных рисков нет открытых
      findings уровня Critical или High.
- [ ] Все Medium и Low findings исправлены либо имеют явного владельца,
      обоснование и срок пересмотра.
- [ ] Рабочее дерево не используется как источник кандидата; сборка читает
      только snapshot `RELEASE_COMMIT`.

## Полный CI

- [ ] На точном commit успешно выполнены `npm ci` и
      `make security-validation` с версиями из
      [../development/ci.md](../development/ci.md).
- [ ] После реализации эксплуатационных целей успешно выполнены
      `make documentation-check`, `make operations-check` и
      `make operations-rehearsal`.
- [ ] Rehearsal использовал только одноразовый Anvil и локальные тестовые ключи;
      подпись и отправка были ограничены локальной цепочкой, а production RPC,
      production secrets и mainnet отсутствовали.
- [ ] Все GitHub required checks для commit завершились успешно.
- [ ] Оператор проверил фактические branch protection или ruleset, запрет
      force-push, обязательное ревью и required checks через GitHub API.
- [ ] Оператор проверил включение Dependabot и доказательство его работы.
- [ ] Редактированное операторское доказательство соответствует
      [evidence/README.md](evidence/README.md); сырые API-ответы, URL, token,
      имена и идентификаторы аккаунтов не добавлены.

Отсутствие любого внешнего операторского доказательства блокирует выпуск. Этот
репозиторий не утверждает, что настройки GitHub уже включены.

## Сборка кандидата

- [ ] Команда выполнена с явным полным commit:

```sh
make release-candidate RELEASE_COMMIT=<40hex>
```

- [ ] Создан только игнорируемый каталог `dist/release/<commit>/`.
- [ ] Целевая платформа равна `linux/amd64`, `CGO_ENABLED=0`.
- [ ] Каталог содержит ровно обязательные файлы из
      [artifacts.md](artifacts.md).
- [ ] `guard-daemon-source.tar` побайтово равен выводу `git archive` с
      каноническим префиксом `guard-daemon-<commit>/`.
- [ ] `RescuerV2.json`, `rescuer-manifest.schema.json` и `LICENSE` побайтово
      взяты из выбранного commit.
- [ ] `guard-daemon.cdx.json` является валидным CycloneDX 1.6 JSON и содержит
      зависимости из закреплённых Go/npm входов.
- [ ] `guard-daemon.intoto.jsonl` содержит одну валидную неподписанную in-toto
      Statement с SLSA Provenance v1.
- [ ] Метаданные JSON не содержат меток времени, имён узла и пользователя,
      рабочего каталога, значений окружения, URL remotes или данных инцидента.
- [ ] `SHA256SUMS` перечисляет все остальные файлы и успешно проверяется.

## Две чистые сборки

- [ ] Один commit собран в двух новых независимых clone без локальных
      сгенерированных файлов и без использования Nix как обязательного условия.
- [ ] В каждой копии установлены те же точные версии инструментов и выполнен
      один и тот же `make release-candidate RELEASE_COMMIT=<40hex>`.
- [ ] Списки путей двух каталогов совпадают.
- [ ] `SHA256SUMS` двух сборок совпадают побайтово.
- [ ] Каждый файл, включая двоичный файл, архив исходного кода, SBOM, метаданные
      выпуска и provenance, совпадает побайтово.
- [ ] Результат сравнения сохранён как редактированное доказательство без
      локальных путей, имён пользователей и URL репозитория.

Различие нельзя объяснять временем или машиной сборки: такие входы запрещены.
При различии кандидат отклоняется и исправляется в новом commit.

## Секреты и содержимое

- [ ] Выполнен поиск секретов в исходном коде и полной Git history командой
      `make secret-scan`.
- [ ] Отдельный поиск секретов прошёл по каждому каталогу
      `dist/release/<commit>/`, включая строки двоичного файла, JSONL, SBOM и tar.
- [ ] В сгенерированном результате нет закрытых ключей, seed-фраз, token,
      credentials, private RPC URL, операторских адресов, персональных данных и
      локальных путей.
- [ ] `guard-daemon-source.tar` содержит русскоязычные runbooks выпуска, эксплуатации и
      развёртывания, lock-файлы и отчёты ревью Tasks 01-10.
- [ ] Кандидат не содержит официальный deployment manifest, секрет подписи,
      подпись или production configuration.

## Граница публикации

- [ ] Кандидат передан независимому ревьюеру Task 11 только локально или через
      утверждённый оператором закрытый канал без секретов.
- [ ] До решения Task 11 не создавались tag, публикация выпуска или публичная
      раздача артефактов.
- [ ] Release scripts не выполняли `push`, изменение remotes или GitHub Release.
- [ ] Агент не выполнял mainnet deployment, отправку транзакций, пополнение или
      подпись.
- [ ] Учтено, что контрольные суммы подтверждают целостность только относительно
      полученного списка и не аутентифицируют издателя.

После заполнения этого списка статус остаётся `КАНДИДАТ, ПУБЛИКАЦИЯ
ЗАБЛОКИРОВАНА`. Разрешение возможно только по итоговому отчёту Task 11 со
словами `РАЗРЕШИТЬ ВЫПУСК`. Подпись и публикация после такого решения остаются
отдельными операторскими процедурами.
