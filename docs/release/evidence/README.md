# Подтверждение внешних условий выпуска без закрытых данных

## Назначение

Этот каталог описывает только минимальную схему и порядок подготовки
операторского подтверждения, из которого удалены закрытые данные. Здесь нет
реальных URL репозитория, ответов GitHub API, токенов, имён операторов,
идентификаторов учётных записей или сведений о закрытой инфраструктуре. Наличие
инструкции не доказывает, что
внешние правила уже включены.

Задача 11 блокируется, пока оператор отдельно не проверит настройки GitHub для
точного коммита выпуска. Агент не запрашивает данные доступа и не выполняет от
имени оператора вызовы API, требующие аутентификации.

## Что проверяет оператор

Оператор сверяет фактическое состояние через интерфейс GitHub или API:

- защита ветки или набор правил применяется к основной ветке;
- прямой `push` и `force-push` запрещены;
- запрос на слияние и минимум одно независимое одобрение обязательны;
- прежние одобрения сбрасываются после изменения набора правок;
- все обсуждения проверки должны быть завершены;
- слияние блокируется до завершения обязательных проверок;
- обход правил разрешён только минимальному утверждённому кругу операторов;
- Dependabot включён и способен создать запрос на слияние;
- обязательные проверки совпадают с точными именами из
  [../../development/ci.md](../../development/ci.md).

Проверка выполняется для точного 40-символьного коммита выпуска. Тела и заголовки
исходных ответов не добавляются в коммит.

## Минимальная обезличенная схема

Оператор переносит только нормализованные результаты в публичное подтверждение
или итоговый отчёт независимой проверки. Допустимая структура:

```json
{
  "schemaVersion": "1",
  "releaseCommit": "<40 lowercase hex>",
  "repository": "REDACTED",
  "branch": "REDACTED",
  "rules": {
    "appliesToBranch": true,
    "directPushBlocked": true,
    "forcePushBlocked": true,
    "pullRequestRequired": true,
    "independentApprovalCountAtLeast": 1,
    "staleApprovalsDismissed": true,
    "reviewThreadsResolved": true,
    "requiredChecksEnforced": true,
    "bypassRestricted": true
  },
  "requiredChecks": [
    { "context": "<exact documented check name>", "required": true }
  ],
  "dependabot": {
    "enabled": true,
    "pullRequestObserved": true
  },
  "operatorAttestation": "VERIFIED_OUTSIDE_AGENT"
}
```

Список `requiredChecks` должен содержать каждое документированное имя, а не один
пример. Схема намеренно не содержит меток времени, URL, владельца репозитория,
логин оператора, числовые идентификаторы, идентификаторы запросов, IP-адреса,
заголовки или тело ответа API.

## Порядок удаления закрытых данных

1. Оператор получает актуальные данные вне среды агента с минимально
   необходимыми правами только на чтение.
2. Оператор проверяет, что ответ относится к нужному репозиторию, основной ветке
   и точному коммиту выпуска.
3. Оператор вручную переносит только булевы результаты и точные публичные имена
   обязательных проверок в нормализованную схему.
4. Все URL, имя владельца и репозитория, имена учётных записей, числовые
   идентификаторы, токены, заголовки, метаданные запросов и
   необязательные поля удаляются.
5. Другой проверяющий сверяет обезличенный результат с исходным ответом, не
   копируя чувствительные значения в комментарии или отчёт.
6. Исходное подтверждение хранится по операторской политике вне репозитория; в
   задачу 11 передаются только обезличенный результат и заверение оператора.

Если после удаления закрытых данных нельзя независимо подтвердить обязательное
правило, проверка считается отсутствующей. Нельзя заменять её предположением на основе
файлов GitHub Actions.

## Запрещённое содержимое

Не добавляйте в этот каталог:

- реальные URL `origin`, `upstream`, репозитория или конечной точки API;
- полный или частичный токен доступа, файл cookie, заголовок авторизации или
  секрет;
- имя пользователя, адрес электронной почты, идентификаторы учётной записи и
  организации, имена людей;
- исходные ответы JSON/GraphQL/REST, заголовки ответа и идентификаторы запроса;
- закрытые имена веток, сведения о внутренней инфраструктуре и локальные пути;
- снимки экрана с нескрытыми данными учётной записи или репозитория;
- метки времени, если они не нужны внешней операторской политике; в публичной
  нормализованной схеме они не нужны.

При случайном попадании чувствительных данных нужно остановить подготовку, не
цитировать значение и сообщить оператору только путь и требуемое действие.
