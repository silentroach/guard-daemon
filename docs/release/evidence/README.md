# Редактированное доказательство внешних условий выпуска

## Назначение

Эта папка описывает только минимальную схему и порядок подготовки
редактированного операторского доказательства. Здесь нет реальных URL
репозитория, ответов GitHub API, токенов, имён операторов, account IDs или
сведений о приватной инфраструктуре. Наличие инструкции не доказывает, что
внешние правила уже включены.

Task 11 блокируется, пока оператор отдельно не проверит средства управления
GitHub для точного release commit. Агент не запрашивает credentials и не
выполняет аутентифицированные API-вызовы от имени оператора.

## Что проверяет оператор

Оператор сверяет фактическое состояние через GitHub UI или API:

- protection/ruleset применяется к основной ветке;
- прямой push и force-push запрещены;
- pull request и минимум одно независимое одобрение обязательны;
- approvals сбрасываются после изменения diff;
- все review threads должны быть разрешены;
- merge блокируется до завершения required checks;
- bypass ограничен минимальным утверждённым кругом операторов;
- Dependabot включён и способен создать pull request;
- required checks совпадают с точными именами из
  [../../development/ci.md](../../development/ci.md).

Проверка выполняется для точного 40-символьного release commit. Тела и заголовки
исходных ответов не коммитятся.

## Минимальная редактированная схема

Оператор переносит только нормализованные результаты в публичное доказательство
или финальный отчёт ревью. Допустимая структура:

```json
{
  "schemaVersion": "1",
  "releaseCommit": "<40 lowercase hex>",
  "repository": "REDACTED",
  "branch": "REDACTED",
  "rules": {
    "appliesToBranch": true,
    "directPushBlocked": true,
    "forcePushBlocked": true,
    "pullRequestRequired": true,
    "independentApprovalCountAtLeast": 1,
    "staleApprovalsDismissed": true,
    "reviewThreadsResolved": true,
    "requiredChecksEnforced": true,
    "bypassRestricted": true
  },
  "requiredChecks": [
    { "context": "<exact documented check name>", "required": true }
  ],
  "dependabot": {
    "enabled": true,
    "pullRequestObserved": true
  },
  "operatorAttestation": "VERIFIED_OUTSIDE_AGENT"
}
```

Список `requiredChecks` должен содержать каждое документированное имя, а не один
пример. Схема намеренно не содержит меток времени, URL, владельца репозитория,
логин оператора, числовые идентификаторы, идентификаторы запросов, IP-адреса,
заголовки или тело ответа API.

## Порядок редактирования

1. Оператор получает актуальные данные вне среды агента с минимально
   необходимыми read-only правами.
2. Оператор проверяет, что ответ относится к нужному repository, основной ветке
   и точному release commit.
3. Оператор вручную переносит только булевы результаты и точные публичные имена
   required checks в нормализованную схему.
4. Все URL, owner/name, logins, numeric IDs, token, headers, request metadata и
   необязательные поля удаляются.
5. Другой ревьюер сверяет редактированный результат с исходным ответом, не
   копируя чувствительные значения в комментарии или отчёт.
6. Исходное доказательство хранится по операторской политике вне репозитория; в
   Task 11 передаётся только редактированный результат и операторская
   аттестация.

Если редактирование не позволяет независимо подтвердить обязательное правило,
проверка считается отсутствующей. Нельзя заменять её предположением на основе
workflow files.

## Запрещённое содержимое

Не добавлять в эту папку:

- реальные URL `origin`, `upstream`, repository или API endpoint;
- полный или частичный access token, cookie, authorization header или secret;
- имя пользователя, адрес email, идентификаторы аккаунта и организации,
  персональные имена;
- сырые ответы JSON/GraphQL/REST, заголовки ответа и идентификаторы запроса;
- private branch names, сведения о внутренней инфраструктуре и локальные paths;
- screenshots с неотретушированными account/repository данными;
- метки времени, если они не нужны внешней операторской политике; в публичной
  нормализованной схеме они не нужны.

При случайном попадании чувствительных данных нужно остановить подготовку, не
цитировать значение и сообщить оператору только путь и требуемое действие.
