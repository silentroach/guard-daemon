# Состав кандидата выпуска

## Каталог

Команда
`make release-candidate RELEASE_COMMIT=<40hex>` создаёт
`dist/release/<commit>/`. Каталог игнорируется Git и не изменяет дерево исходного
кода.
Имена и набор файлов фиксированы:

| Файл | Назначение | Детерминированный источник |
|---|---|---|
| `guard-daemon-linux-amd64` | Двоичный файл для единственной целевой платформы выпуска `linux/amd64`, `CGO_ENABLED=0` | Пакеты Go из выбранного коммита |
| `guard-daemon-source.tar` | Точный снимок отслеживаемого дерева исходного кода | `git archive` с фиксированным префиксом выпуска |
| `LICENSE` | Условия распространения | `LICENSE` из выбранного коммита |
| `RescuerV2.json` | Проверенный контрактный артефакт | `artifacts/contracts/RescuerV2.json` из выбранного коммита |
| `rescuer-manifest.schema.json` | Схема будущего манифеста развёртывания | `deployments/schema/rescuer-manifest.schema.json` из выбранного коммита |
| `guard-daemon.cdx.json` | Перечень компонентов ПО | Собственный генератор на Python, CycloneDX 1.6 JSON |
| `release-candidate.json` | Машиночитаемое описание коммита, целевой платформы и состава | Собственный генератор на Python |
| `guard-daemon.intoto.jsonl` | Заявление об исходных данных и результатах сборки | Неподписанный документ `in-toto Statement`, SLSA Provenance v1 |
| `SHA256SUMS` | SHA-256 всех остальных файлов | Собственный генератор на Python после создания содержимого |

Любой дополнительный или отсутствующий файл является ошибкой. Русскоязычные
руководства, файлы фиксации версий зависимостей и отчёты независимой проверки
задач 01-10 входят в `guard-daemon-source.tar`, поскольку берутся из коммита
выпуска. Они не копируются рядом отдельным неконтролируемым набором.

## Двоичный файл

Двоичный файл строится из снимка коммита, а не из текущей рабочей копии. Параметры
сборки фиксированы:

```text
GOOS=linux
GOARCH=amd64
GOAMD64=v1
CGO_ENABLED=0
GOFIPS140=off
GOWORK=off
GOMODCACHE=/var/tmp/guard-daemon-release-go-mod-v1
-mod=readonly
-trimpath
-buildvcs=false
-ldflags="-s -w -buildid= -X guard-daemon/internal/buildinfo.ReleaseCommit=<commit>"
```

Другие операционные системы, архитектуры или режимы CGO не являются официальной
целевой платформой и требуют нового явно спроектированного профиля. Генератор не
встраивает время, имя машины, пользователя, путь рабочей копии или значения окружения.
Отладочные секции и таблица символов исключены флагами `-w -s`: они не нужны
работающему процессу и не входят в канонический артефакт выпуска.
Go, npm и Python запускаются через абсолютный `/usr/bin/env -i` и явно заданный
список разрешённых значений. Поэтому экспортированная функция оболочки `env`,
локальные `GOFIPS140`,
`GOCACHEPROG`, `GOWORK`, `NODE_OPTIONS`, `npm_config_*` и `PYTHON*` не могут
изменить кандидата. Фиксированный `GOMODCACHE` создаётся
с исключительным доступом и режимом `0700`, проверяется через `go mod verify` и
удаляется после сборки; стабильный абсолютный путь исключает влияние путей кэша
модулей на различия между двоичными файлами.
Для сборки выпуска требуется официальный дистрибутив Go 1.26.5. Совпадающей
строки версии недостаточно: изменённый набор инструментов, который встраивает
локальные пути пакетного менеджера, не является каноническим. Сценарий сборки
завершается с ошибкой, если двоичный файл содержит пути рабочей копии, каталога результата,
`GOROOT` или `/nix/store/`.
Проверка выполняется командой `/usr/bin/strings`, указанной абсолютным путём, по суффиксу каталога
и полным префиксам `directory/`, поэтому экспортированная функция оболочки не
может скрыть результат, а сходный префикс соседнего каталога не считается путём
внутри проверяемого каталога. Неоднозначные корневые пути, состоящие из одного компонента,
например `/go`, запрещены до сканирования. Допустима системная символическая
ссылка `/usr/bin/strings`, управляемая пакетным менеджером; поиск команды
оболочкой не используется.
Поддерживаемая точка входа `make release-candidate` до запуска сценария сборки
создаёт новую оболочку через абсолютные `/usr/bin/env -i` и
`/bin/bash --noprofile --norc`. Сценарий сборки дополнительно отклоняет уже
импортированные функции оболочки, `BASH_ENV` и `ENV`, поэтому экспортированная
функция `git` или обработчик запуска не могут подменить проверку коммита и архива
исходного кода до запуска внутреннего процесса с очищенным окружением.
Документированный фиксированный `GOMODCACHE` является каноническим параметром
сборки, а не путём, зависящим от хоста. Nix разрешён для остальных локальных
проверок, но изменённую Nix версию Go нельзя использовать как компилятор
официального кандидата.

## Архив исходного кода

`guard-daemon-source.tar` является точным результатом одной операции:

```sh
GIT_ATTR_NOSYSTEM=1 git -c core.attributesFile=/dev/null \
  -c tar.umask=0002 archive --format=tar \
  --prefix="guard-daemon-<commit>/" <commit>
```

Префикс является частью канонического формата. Запрещено менять его, заголовки
tar-архива, повторно упаковывать или сжимать результат. Коммит должен быть
локальным и задаваться полным неизменяемым SHA. В архив попадают только
отслеживаемые пути этого коммита; неотслеживаемые, игнорируемые и локальные операторские файлы
исключены.
Сценарий сборки дополнительно отключает системные и глобальные атрибуты и
отклоняет локальный файл репозитория `info/attributes`, а также
`assume-unchanged` и `skip-worktree`.
Локальный `tar.umask` принудительно переопределяется каноническим `0002`, поэтому
настройки Git двух рабочих копий не вносят в архив исходного кода различия,
зависящие от среды.

`LICENSE`, `RescuerV2.json` и `rescuer-manifest.schema.json` извлекаются из того
же коммита. Генератор должен завершиться с ошибкой, если файл отсутствует,
является символической ссылкой вместо обычного файла или отличается от
соответствующего содержимого в `guard-daemon-source.tar`.

## SBOM

Собственный генератор репозитория создаёт `guard-daemon.cdx.json` на Python без
внешнего SBOM-сервиса. Документ использует `bomFormat: CycloneDX`,
`specVersion: 1.6` и включает основной компонент, модули Go из
`go.mod`/`go.sum` и `go mod graph`, пакеты npm из `package-lock.json`, их версии
и граф зависимостей. Порядок `components`,
`dependencies`, `properties` и ключей стабилен.

Необязательные поля, нарушающие воспроизводимость, запрещены: `serialNumber`,
`metadata.timestamp`, имена узла и пользователя, абсолютный путь и значения
окружения. SBOM описывает закреплённые исходные данные, но сам по себе не
доказывает, кто его создал.

## Метаданные кандидата

`release-candidate.json` содержит только воспроизводимые данные:

- версию собственной схемы метаданных;
- полный коммит выпуска;
- полный хеш дерева коммита выпуска;
- целевую платформу `linux/amd64` и `cgoEnabled: false`;
- фиксированные пути и SHA-256 двоичного файла, исходного архива, контрактного
  артефакта, схемы манифеста и SBOM.

Файл не содержит URL удалённых репозиториев, ветки или тега, времени, сведений
об узле или пользователе, текущего каталога, окружения или адресов развёртывания.
Его собственный SHA-256 находится только в `SHA256SUMS`, чтобы не создавать цикл.

## Сведения о происхождении сборки

`guard-daemon.intoto.jsonl` содержит ровно одну JSON-строку. Это in-toto
Statement v1 с предикатом SLSA Provenance v1. Поле `subject` перечисляет
созданные до документа о происхождении файлы и их SHA-256. `buildDefinition`
фиксирует полный коммит, целевую платформу выпуска и стабильный тип сборки
репозитория. `runDetails` не включает метки времени, среду выполнения, имена
узла и пользователя, дамп окружения или персональный URL репозитория.
Список разрешённых исходных данных также содержит SHA-256 фактически выполненного
`scripts/build-release-candidate.sh`, совпадающего с файлом в архиве исходного
кода.

Документ `in-toto Statement` намеренно не подписан. Он позволяет сверить
заявленные исходные данные и результаты, но не подтверждает подлинность издателя
или сборщика. Текущий процесс GitHub Actions не выдаёт токен OIDC и не
подписывает сведения о происхождении.

## Контрольные суммы

`SHA256SUMS` содержит SHA-256 каждого другого файла каталога, по одному пути на
строку, в байтовой сортировке по имени. Сам `SHA256SUMS` не перечисляется, чтобы
не создавать рекурсию. Проверка на Linux выполняется из каталога кандидата:

```sh
sha256sum --check --strict SHA256SUMS
```

Совпавшая сумма доказывает только отсутствие изменения относительно полученного
`SHA256SUMS`. Если атакующий заменил и файл, и список сумм, эта проверка не
обнаружит подмену издателя. Для проверки подлинности нужна отдельная допустимая
подпись: CI без постоянных ключей с проверенными правилами идентификации OIDC
либо подпись оператора вне агента.

## Что не входит в кандидат

В каталог запрещено включать:

- официальный манифест развёртывания или рабочие адреса;
- закрытые ключи, мнемонические фразы, токен API, данные доступа к RPC и `.env`;
- ключ или секрет подписи, токен OIDC или автоматически созданную подпись;
- логи, метки времени, имена узла и пользователя, абсолютные локальные пути и
  дамп окружения;
- тег Git, данные GitHub Release или результат API удалённого сервиса;
- базу состояния, контрольные точки, реестр бюджета или операторскую резервную
  копию.

Официальный манифест развёртывания создаётся только после появления этого
неизменяемого кандидата. До завершения задачи 11 ни один файл каталога нельзя
публиковать.
