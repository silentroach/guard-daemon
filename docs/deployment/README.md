# Развёртывание RescuerV2

Этот каталог разделяет безопасную локальную проверку, операторское действие в
публичной сети и независимую эксплуатационную аттестацию. Ни один документ не
утверждает готовность к основной сети и не подтверждает, что публичное
развёртывание или локальная репетиция уже выполнены.

## Порядок чтения

1. [`local-verification.md`](local-verification.md) — проверка артефакта, план
   без отправки и локальный Anvil.
2. [`manifest-attestation.md`](manifest-attestation.md) — связь коммита выпуска,
   артефакта, манифеста и состояния сети.
3. [`operator-activation.md`](operator-activation.md) — процедура, которую в
   публичной сети выполняет только оператор.
4. [`../migration/delegation.md`](../migration/delegation.md) — граница смены
   реализации и делегации EIP-7702.
5. [`../migration/rollback-emergency.md`](../migration/rollback-emergency.md) —
   экстренная остановка, сохранение свидетельств и ограничения отката.

## Обязательные границы

- Агент не отправляет транзакции, не пополняет `sponsor`, не получает ключи и не
  выполняет команды активации публичной сети.
- Без `--broadcast` CLI развёртывания не использует RPC или ключ и требует только
  идентификатор сети, `destination` и `sponsor`; значения `DEPLOYMENT_RPC_URL` и
  `DEPLOYER_PRIVATE_KEY` в этом режиме не читаются.
- Режим с отправкой допустим только с обязательными лимитами
  `gas-limit`, максимальной и приоритетной комиссии и полной стоимости газа, а
  также полной проверки каталога кандидата по `release-candidate.json` и канонического
  реестра восстановления. RPC публичной сети передаётся только через
  `DEPLOYMENT_RPC_URL`, а не через argv; `--rpc-url` допустим только для
  локального идентификатора сети `31337` или игнорируемого плана без отправки.
- Официальный манифест связывается с полным коммитом выпуска через
  `source.kind=git-commit`; SHA-256 артефакта в нём совпадает с кандидатом
  выпуска.
- Чтение через единственный RPC после развёртывания носит предварительный характер. Перед
  включением подписания демон должен стартовать с `DRY_RUN=false` и
  `EMERGENCY_STOP=true`, без ключей, и провести аттестацию двумя независимыми
  поставщиками на общем финализированном блоке.
- Подписанная транзакция развёртывания сохраняется в записи восстановления с
  режимом `0600` до отправки. Неоднозначный результат запрещает новое
  развёртывание до сверки оператором. Для идентификаторов сетей `1`, `56` и `137`
  реестр всегда расположен в
  `/var/lib/guard-daemon-operator/deployment-recovery`, имеет режим `0700` и
  владельца `root:root` и не переопределяется. CLI повторно сверяет канонический
  путь, идентификатор устройства, inode, режим и владельца непосредственно перед
  блокировкой и записью. Только для локального идентификатора сети `31337`
  обязателен `--recovery-directory` с заранее созданным временным каталогом `0700`
  вне каталога кандидата и рабочей копии Git.
- Развёртывание в публичной сети запускается только из аутентифицированных
  каталогов с владельцем root
  `/usr/lib/guard-daemon/deployment/<commit>` и
  `/usr/lib/guard-daemon/candidates/<commit>`. Обычная рабочая копия и изменяемый
  каталог `node_modules` запрещены; секреты передаются только новому процессу
  после отдельной предварительной проверки без секретов.
- Для локального идентификатора сети `31337` проверяется чистая рабочая копия и
  отдельно отклоняются флаги индекса Git `assume-unchanged` и `skip-worktree`;
  одного пустого `git status` недостаточно.
- Скомпрометированный ключ `source` остаётся скомпрометированным. Развёртывание и
  делегация не гарантируют победу в гонке и не разрешают повторно использовать
  прежний EOA.

## Блокирующие условия

Публичная отправка заблокирована, если проверяемый кандидат выпуска, CLI,
пределы стоимости или происхождение `git-commit` не соответствуют этим
документам. Постоянные хранилища наблюдателя и бюджета также не поддерживают
безопасную смену `rescuer` на месте. Поэтому документация задаёт проверяемые
условия активации, но сама по себе не является разрешением на действия в
публичной сети.
