# Аттестация кандидата выпуска и манифеста развёртывания

## Цель

Аттестация связывает четыре объекта: неизменяемый коммит выпуска, точные байты
канонического артефакта, транзакцию развёртывания и состояние контракта в
финализированной цепочке. Ни доверие к одному RPC, ни успешная квитанция, ни
совпадение одной getter-функции сами по себе эту связь не доказывают.

## Кандидат выпуска

`release-candidate.json` создаётся только после появления неизменяемого коммита
выпуска. Для развёртывания существенны:

- полный 40-символьный коммит из строчных шестнадцатеричных символов;
- SHA-256 точных байтов `artifacts/contracts/RescuerV2.json` в форме
  `sha256:<64 строчных шестнадцатеричных символа>`.

Смысловая форма записи:

```json
{
  "releaseCommit": "<40 строчных шестнадцатеричных символов>",
  "artifacts": {
    "contract": {
      "path": "RescuerV2.json",
      "sha256": "sha256:<64 строчных шестнадцатеричных символа>"
    }
  }
}
```

Это сокращённое описание обязательной связи, а не полная схема и не разрешение
вручную изготовить метаданные. Строгий анализатор проверяет полный объект
кандидата, его платформу и фиксированный набор артефактов. Неизвестные поля,
повторяющиеся JSON-ключи, сокращённый коммит и несовпадающий хеш должны приводить
к отказу до обращения к RPC и чтения ключа.

## Официальный манифест

Для публичного развёртывания манифест версии `1` обязан содержать:

- `source.kind` со значением `git-commit`;
- `source.value`, точно равный полному коммиту из кандидата выпуска;
- `artifact.sha256`, точно равный хешу из кандидата выпуска и хешу
  прочитанных байтов канонического артефакта;
- идентификатор сети, адрес контракта, номер и хеш блока, а также хеш транзакции
  развёртывания;
- версию компилятора и точные настройки;
- Keccak-256 и длину связанного исполняемого кода;
- аргументы конструктора и неизменяемые `destination`, `self`, `sponsor`.

Любой другой `source.kind` не удовлетворяет требованиям официального кандидата
выпуска. Происхождение нельзя переименовывать в `git-commit` без повторного
создания манифеста из проверенного выпуска.

Манифест не содержит ключ, подпись, RPC URL, набор параметров авторизации или
операторские секреты. Путь манифеста не должен совпадать с артефактом, кандидатом
выпуска или операторской конфигурацией, в том числе через символическую или
жёсткую ссылку. Сам манифест и его заранее существующий родитель должны
находиться вне каталога кандидата и рабочей копии Git; родитель не может быть
символической ссылкой.

## Уровни проверки

### 1. Локальная воспроизводимость

`npm run artifacts:verify` повторно компилирует закреплённый исходный код и
побайтно сравнивает артефакт. Затем вычисляется SHA-256 файла и сверяется с
кандидатом выпуска. Проверка коммита выполняется до сетевого доступа.

### 2. Ограниченное построение транзакции

CLI развёртывания допускает отправку только для сетей с идентификаторами `1`,
`56` и `137` и для локальной сети с идентификатором `31337`, проверяет роли,
строит точные данные конструктора и
явно устанавливает `gasLimit`, `maxFeePerGas` и `maxPriorityFeePerGas`. Он
отклоняет транзакцию, если `gasLimit * maxFeePerGas` превышает
`max-total-cost-wei`. CLI не определяет модель дополнительной комиссии сети;
оператор обязан отдельно заблокировать сеть, где полная стоимость не ограничена
полями подписанной транзакции.

До отправки точная подписанная транзакция сохраняется в новой записи
восстановления с режимом `0600`. Манифест создаётся без перезаписи только после
получения квитанции и предварительного чтения. Для публичной сети используется
фиксированный реестр `/var/lib/guard-daemon-operator/deployment-recovery`
(`0700 root:root`);
локальный идентификатор сети `31337` требует явный временный
`--recovery-directory`. Канонические пути, идентификаторы устройств и inode
реестра и родительского каталога манифеста повторно проверяются перед записью. Манифест
публичной сети создаётся только в фиксированном каталоге
`/var/lib/guard-daemon-operator/deployment-manifests` (`0700 root:root`), затем
оператор отдельно устанавливает проверенную копию в `/etc`.
Существующая запись той же пары «сеть + `sponsor`» независимо от коммита либо
существующий манифест блокирует новый запуск, чтобы неоднозначный исход не
превратился в повторное развёртывание.

В рабочей среде используются только аутентифицированные кандидат выпуска и
средства развёртывания, принадлежащие root, а метаданные Git не читаются. При
проверке рабочей копии для локального идентификатора сети `31337` отклоняются
расположенный в репозитории файл `info/attributes`, `assume-unchanged` и
`skip-worktree`, в том числе после повторной проверки битов индекса вслед за
каноническим `git archive`. RPC URL публичной сети поступает только из
`DEPLOYMENT_RPC_URL`;
`--rpc-url` оставлен только для локального `31337` и режима плана, чтобы
данные доступа не попадали в argv.

### 3. Предварительное чтение одним RPC

После получения квитанции сценарий развёртывания через тот же RPC сверяет
исполняемый код и getter-функции по блоку развёртывания и только затем атомарно
публикует манифест. Это полезная самопроверка против ошибки конструктора или
адреса, но единственный RPC остаётся недоверенным. Такой результат нельзя
называть окончательной аттестацией.

### 4. Эксплуатационная аттестация двумя поставщиками

Окончательную проверку допуска выполняет сам демон при `DRY_RUN=false` и
`EMERGENCY_STOP=true` без приватных ключей. Минимум два независимо настроенных
HTTP-поставщика чтения должны иметь разные конечные точки, домены доверия и
экземпляры клиента. Они обязаны согласовать общий финализированный номер и хеш
блока.

На этом общем состоянии каждый поставщик подтверждает:

1. Ожидаемый идентификатор сети.
2. Финализацию блока развёртывания и его хеш.
3. Точную CREATE-транзакцию и окончательную квитанцию об успешном выполнении.
4. Адрес созданного контракта.
5. Полное совпадение исполняемого кода со связанным каноническим артефактом.
6. `destination`, `self` и `sponsor` по вызовам, закреплённым хешем блока.

RPC отправки не участвует в кворуме чтения. При расхождении высоты допускается
только переход к общему более низкому финализированному блоку с тем же хешем у
обоих поставщиков. Отсутствующий или повреждённый ответ, тайм-аут,
неподтверждённая транзакция, неуспешная квитанция или расхождение любого поля
означает отказ.

## Свидетельство

Безопасный пакет свидетельств содержит кандидата выпуска, полный коммит,
SHA-256 артефакта и манифеста, публичные хеши транзакции и блока, а также
обезличенный результат проверки при запуске. Он не содержит RPC URL с данными доступа,
подписанные транзакции в исходном виде до включения платных действий, ключи, подписи или данные
авторизации.

Положительная локальная проверка или чтение через один RPC не заменяет запуск
демона с двумя независимыми поставщиками. Даже прохождение всех проверок не
гарантирует победу в гонке за скомпрометированный `source` и не означает
готовность к основной сети.
