# Наблюдение через локальный Unix-сокет

Демон публикует только локальный HTTP-интерфейс в JSON через
`/var/lib/guard-daemon/diagnostics.sock` при системной установке. TCP-порт не
открывается. Сокет имеет режим `0600` и принадлежит пользователю
`guard-daemon`; сборщик должен работать на том же хосте с явно предоставленным
доступом. Не ослабляйте режим сокета.

```bash
curl --silent --show-error --unix-socket /var/lib/guard-daemon/diagnostics.sock --write-out '\nHTTP %{http_code}\n' http://localhost/healthz
curl --silent --show-error --unix-socket /var/lib/guard-daemon/diagnostics.sock http://localhost/metrics
```

Имя `localhost` здесь является только обязательной частью HTTP-запроса. Сетевое
соединение к нему не выполняется.

## `/healthz`

Ответ всегда имеет `Content-Type: application/json`. Верхнее поле `status`
описывает весь процесс, а ключи объекта `networks` являются десятичными
`chain_id`. Для каждой сети возвращаются все поля:

```json
{
  "status": "healthy_idle",
  "networks": {
    "1": {
      "status": "healthy_idle",
      "rpc_degraded": false,
      "budget_blocked": false,
      "ambiguous_rescue": false,
      "stopped": false
    }
  }
}
```

Состояния имеют строгий приоритет:

| `status` | HTTP | Точное условие | Действие оператора |
|---|---:|---|---|
| `healthy_idle` | `200` | Ни одно условие отказа не активно | Продолжать наблюдение |
| `degraded_rpc` | `503` | Хотя бы для одной сети активно `rpc_degraded` | Проверить оба источника чтения, WebSocket, HTTP и политику исходящих соединений; не переключаться на один источник как на доверенный |
| `blocked_budget` | `503` | Хотя бы для одной сети активно `budget_blocked` | Остановить ожидание платных действий, проверить остатки и резервы; не обнулять состояние |
| `ambiguous_rescue` | `503` | Хотя бы одна операция имеет неоднозначный исход | Считать nonce и средства потенциально затронутыми; не отправлять заменяющую транзакцию вручную до сверки |
| `stopped` | `503` | Включён необратимый для текущего процесса запрет платных действий | Для `EMERGENCY_STOP=true` это ожидаемое безопасное состояние; не перезапускать процесс по кругу |

Приоритет равен `stopped`, затем `ambiguous_rescue`, `blocked_budget`,
`degraded_rpc`, `healthy_idle`. Поэтому менее приоритетное условие может быть
видно только в логических полях сети, а не в её `status`. Общее состояние
агрегирует условия всех сетей. При `stopped` поле `stopped` истинно для каждой
сети.

После создания процесса каждая сеть начинается с `rpc_degraded=true`. Условие
снимается только после открытия рабочей сетевой сессии. Свежесть журнала не
участвует в расчёте.

Отсутствующий сокет при активной, по мнению systemd, службе является отдельным
отказом диагностики или запуска. Проверяйте одновременно `systemctl is-active`
и доступность сокета.

## `/metrics`

`GET /metrics` возвращает HTTP `200` с объектом следующей формы:

```json
{
  "global_budget": {
    "spent_wei": "0",
    "reserved_wei": "0",
    "remaining_wei": "0"
  },
  "networks": {
    "1": {
      "queue_depth": 0,
      "candidates": 0,
      "attempts": 0,
      "budget": {
        "spent_wei": "0",
        "reserved_wei": "0",
        "remaining_wei": "0"
      },
      "rpc_errors": 0,
      "reconnects": 0,
      "lost_races": 0,
      "active_ambiguous": 0,
      "total_ambiguous": 0,
      "delegation_state": 1
    }
  },
  "active_alerts": 0,
  "alerts": []
}
```

`last_successful_reconciliation` добавляется к сети только после первой
успешной сверки и содержит время UTC в формате RFC 3339 с дробной частью при её
наличии.

### Поля бюджета

`spent_wei`, `reserved_wei` и `remaining_wei` являются десятичными строками, а
не числами JSON. Это исключает потерю точности `uint256`. `global_budget`
показывает накопительные общие значения, а `networks.<chain_id>.budget` —
накопительные значения сети. В режиме без отправки они могут оставаться
нулевыми; ноль сам по себе не доказывает исправность бюджета.

### Поля сети

| Поле | Тип и смысл |
|---|---|
| `queue_depth` | `uint64`, текущая глубина устойчивой очереди |
| `candidates` | `uint64`, число кандидатов, переданных обработчику за время текущего процесса |
| `attempts` | `uint64`, число начатых попыток за время текущего процесса |
| `budget` | Объект сетевого накопительного бюджета в wei |
| `rpc_errors` | `uint64`, ошибки RPC, отмеченные за время текущего процесса |
| `reconnects` | `uint64`, повторные открытия сетевого поколения за время текущего процесса |
| `lost_races` | `uint64`, классифицированные проигранные гонки за время текущего процесса |
| `active_ambiguous` | `uint64`, текущие неоднозначные операции, восстановленные из устойчивого состояния |
| `total_ambiguous` | `uint64`, открытия неоднозначного исхода за время текущего процесса |
| `delegation_state` | Закрытое числовое состояние делегации |
| `last_successful_reconciliation` | Необязательная отметка последней полностью успешной сверки |

Счётчики текущего процесса не следует складывать после перезапуска без метки
экземпляра сборщика. Денежное состояние и открытые неоднозначные операции
восстанавливаются из диска, но это не превращает все счётчики в сохраняемые.

Значения `delegation_state`:

| Значение | Смысл |
|---:|---|
| `1` | `unknown`: состояние ещё не доказано либо чтение не удалось |
| `2` | `expected`: после операции подтверждена ожидаемая делегация |
| `3` | `missing`: значение предусмотрено схемой; текущий рабочий путь его не выставляет |
| `4` | `unexpected`: обнаружена отсутствующая или иная делегация после операции |

Не интерпретируйте `1` как нормальную делегацию и не интерпретируйте `2` как
доказательство безопасности `source`: владелец скомпрометированного ключа может
заменить делегацию позже.

## Активные предупреждения

`active_alerts` равно числу элементов `alerts`. Каждый элемент содержит только
строковый `chain_id` и закрытый `code`, например:

```json
{
  "chain_id": "1",
  "code": "ambiguous_rescue"
}
```

Поддерживаются ровно следующие коды:

| Код | Причина активации | Условие снятия |
|---|---|---|
| `rpc_degraded` | Сетевое поколение завершилось ошибкой или не может быть открыто | Новая рабочая сессия сети успешно открыта |
| `budget_blocked` | Общий или сетевой снимок бюджета блокирует платное действие | Следующий успешный снимок больше не заблокирован |
| `ambiguous_rescue` | В устойчивом состоянии есть хотя бы одна неоднозначная операция | Сверка не находит активных неоднозначных операций |
| `paid_actions_stopped` | Процесс создан с `EMERGENCY_STOP=true` | Новый процесс создан с `EMERGENCY_STOP=false` |
| `delegation_unexpected` | Проверка после квитанции обнаружила не ожидаемую делегацию | Последующая проверка после квитанции подтверждает ожидаемую делегацию |
| `reconciliation_stale` | Проход сверки завершился хотя бы с одной нефатальной ошибкой | Следующий проход сверки полностью успешен |

`delegation_unexpected` и `reconciliation_stale` не меняют `/healthz` напрямую;
их обязательно проверяют в `alerts`. Снятые предупреждения в ответ не входят.
Состояние дедупликации сохраняется на диске по паре `chain_id+code`, а повторное
уведомление ограничено `ALERT_COOLDOWN`. Встроенный получатель записывает
структурированное событие в журнал; удалённая доставка предупреждений в демоне
не реализована.

## Минимальные правила оповещения

Система наблюдения должна применять следующие правила без анализа свежести
строк журнала:

| Условие | Срочность |
|---|---|
| systemd считает службу активной, но сокет отсутствует или оба запроса не разбираются как JSON | Немедленное вмешательство |
| `ambiguous_rescue`, `delegation_unexpected` или `reconciliation_stale` активен | Немедленное вмешательство с запретом ручной отправки до выяснения |
| `budget_blocked` активен или `remaining_wei` достиг утверждённого оператором порога | Немедленная проверка бюджета; пределы не повышать автоматически |
| `rpc_degraded` активен | Проверка обоих независимых источников и исходящей сети; длительность эскалации задаёт операторский норматив |
| `paid_actions_stopped` активен при объявленном аварийном режиме | Ожидаемое предупреждение, подтверждающее запрет платных действий |
| `paid_actions_stopped` активен вне объявленного аварийного режима | Немедленная проверка конфигурации и процедуры запуска |
| `queue_depth` устойчиво растёт, а `last_successful_reconciliation` отсутствует или старше операторского норматива | Проверка очереди, RPC и сверки |
| Увеличиваются `lost_races`, `rpc_errors` или `reconnects` | Анализ тенденции; автоматическое повышение комиссии запрещено |

Порог длительности и размер очереди зависят от включённых сетей и задаются во
внешней системе наблюдения. Демон не публикует готовые временные пороги и не
поддерживает метки адресов токенов, инцидентов или URL RPC.
