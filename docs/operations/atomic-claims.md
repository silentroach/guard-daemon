# Атомарный клейм и перевод ERC-20

Запрос клейма исполняется одной EIP-7702 транзакцией: авторизация на проверенный
RescuerV2, вызов `executeAndSweep(target, data, [token])` и перевод полученного
токена на закреплённый `destination`. `valueWei` передаётся платной функции клейма
и входит в резерв расходов sponsor вместе с комиссиями. После отката списываются
только комиссии; после успешной транзакции учитывается также отправленный ETH.

Используется актуальный канонический RescuerV2 с `payable executeAndSweep`.
Старые развёртывания с тем же именем могут не принимать ETH и отклоняются
проверкой байткода и манифеста при запуске.

## Подготовка запроса

Оператор получает актуальные calldata у системы, предоставляющей клейм. Демон
не получает подписи клейма из стороннего API и не переиспользует данные старой
транзакции автоматически. На одну сеть задаётся один файл `CLAIM_REQUEST_<N>`.
Пример структуры с тестовыми адресами target/token и заглушкой calldata:

```json
{
  "chainId": 8453,
  "target": "0x1000000000000000000000000000000000000001",
  "data": "0x12345678",
  "valueWei": "0",
  "token": "0x2000000000000000000000000000000000000002",
  "minimumReceivedRaw": "1000000",
  "gasLimit": 500000,
  "maximumCostWei": "1000000000000000",
  "validUntil": 1893456000
}
```

Замените target, calldata, платёж, токен и срок данными своего клейма.
`validUntil` — последний допустимый момент начала отправки, Unix-время в секундах.
Он не отменяет уже опубликованную транзакцию и не заменяет проверку срока подписи
самим контрактом клейма. Calldata ограничены 16 КиБ, весь файл — 64 КиБ.

Токен должен входить в выбранную сетевую политику. Для доверенного токена
`minimumReceivedRaw` не ниже минимума из `TOKEN_VALUE_RULES_<N>`, а
`maximumCostWei` не выше соответствующего предела стоимости. Для недоверенного
разрешённого токена действует `UNKNOWN_TOKEN_MAX_TRANSACTION_COST_WEI_<N>`.
Все значения остаются в пределах сетевого и общего бюджета. Gas limit запроса
задаётся отдельно, поскольку клейм может быть дороже простого перевода.

Файл установите как `root:guard-daemon 0640` в доступный службе каталог,
например `/etc/guard-daemon/claims/`, и укажите путь в публичной конфигурации.
Подписанные calldata не следует публиковать или записывать в журналы.

## Выполнение и перезапуск

В рабочем режиме запрос ставится в постоянную очередь сразу после открытия
сетевого сеанса; ожидать входящего `Transfer` не требуется. Нулевой баланс
токена на source допустим. Перед отправкой проверяются срок, резерв sponsor,
nonce, симуляция точного вызова с авторизацией и `value`, а также оценка газа.

Один и тот же запрос имеет неизменный ID, включающий все его параметры.
Завершённый запрос не исполняется повторно после переподключения или рестарта;
его итоговая запись сохраняется. Просроченный запрос не подписывается, а уже
подписанный после истечения срока только согласуется по квитанциям без новых
отправок. Не меняйте и не удаляйте запрос с незавершённой операцией: потребуется
восстановить исходный файл для согласования. Параметры читаются при запуске.

Dry-run проверяет структуру запроса, но не ставит платный клейм в очередь и не
подписывает EIP-7702. Проверка полного пути выполняется локальными тестами с
тестовыми ключами; рабочая симуляция выполняется непосредственно перед отправкой.

После квитанции проверяются текущая делегация, отсутствие остатка данного токена
на source и прирост destination не меньше исходного баланса source плюс
`minimumReceivedRaw`. Результат ERC-20 остаётся `token-reported`.
Параметр минимального получения проверяется после исполнения и сам по себе
не откатывает уже выполненную транзакцию; on-chain минимум должен обеспечивать
сам контракт клейма, если он необходим.

## Base и комиссии

Для Base требуется `NETWORK_FEE_MODE_BASE=estimated`. До подписи кворум оценивает
L1/operator fee; после квитанции учитываются фактические комиссии. Резерв
`CHAIN_OVERHEAD_MAX_WEI_BASE` должен покрывать предварительную оценку. Если
фактическая стоимость превысила зарезервированную, ledger учитывает её полностью
и блокирует новые расходы. Это блокирование сохраняется после рестарта; состояние
не удаляют для сброса ограничения.

Состояние с новыми claim-записями или политикой расчётных комиссий несовместимо
с `v0.0.1`. Откат бинарника после их появления требует проверки совместимости;
откатывать базу расходов на старый снимок нельзя.

`MIN_PRIORITY_FEE_PER_GAS_WEI_BASE` позволяет задать нижнюю границу tip, сохраняя
верхние пределы цены газа и общие бюджеты. Это не гарантирует порядок включения.

При развёртывании RescuerV2 в Base дополнительно укажите `--fee-mode estimated`.
CLI проверяет оценку полной комиссии перед подписью и непосредственно перед
отправкой. `--max-total-cost-wei` для Base является расчётным пределом; остальные
проверки выпуска, ролей, восстановления и манифеста сохраняются.

Атомарность исключает вклинивание между клеймом и переводом, но конкурирующая
авторизация может опередить всю транзакцию. Отдельный on-chain контракт,
проверяющий делегацию до вызова source, в этот путь пока не входит; газ и `value`
при проигранной гонке могут попасть под исполнение чужой делегации. Общая модель
описана в [документе безопасности](../security/rescuer-v2.md).
