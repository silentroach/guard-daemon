# guard-daemon: безопасное восстановление активов

`guard-daemon` наблюдает за поступлениями на скомпрометированную учётную запись
EVM (EOA) и пытается перевести разрешённые активы на заранее заданный безопасный
адрес. Комиссии оплачивает отдельная роль `sponsor`. Для выполнения операции
используется EIP-7702 и контракт `RescuerV2`.

Проект не устраняет компрометацию. Ключ роли `source` остаётся
скомпрометированным, и атакующий может подписывать конкурирующие транзакции и
авторизации EIP-7702.
Успех `guard-daemon` не гарантирован. После завершения попыток прежнюю EOA нельзя
снова использовать для хранения ценных активов или регистрации в новых системах.

Успешная квитанция транзакции, ответы `balanceOf`, события `Transfer` и другие
данные контракта токена не доказывают экономическую ценность актива. Результат
операции с ERC-20 классифицируется только как `token-reported`.

## Состояние проекта

Репозиторий не заявляет о готовности к промышленной эксплуатации. В нём нет
официальных манифестов и адресов развёртывания. Запись сети во
внутреннем реестре означает только, что конфигурация знает её имя, идентификатор,
набор известных токенов и экономический профиль. Это не подтверждает наличие
безопасного контракта, поддержку EIP-7702 конкретной сетью или готовность к
платным операциям.

## Модель работы

Для каждой явно включённой сети демон:

1. сохраняет WebSocket-события как предварительные сигналы;
2. восстанавливает пропуски и подтверждает события по согласованному
   финализированному блоку через два независимых RPC для чтения;
3. применяет политику `known-only`, `allowlist` или явный режим `all`;
4. сохраняет кандидатов и инциденты в локальном состоянии;
5. в режиме dry-run выполняет только сетевые чтения и `EstimateGas`;
6. в рабочем режиме допускает платную попытку только после аттестации, проверки
   средства подписи, лимитов расходов, резерва `sponsor` и правила ценности
   токена;
7. после получения квитанции транзакции проверяет постусловия, не повышая
   результат ERC-20 выше
   `token-reported`.

Компонент наблюдения не получает доступ к средству подписи или отправке. Один
координатор на пару «сеть + `sponsor`» последовательно обрабатывает nonce и
отправку. Постоянная очередь, контрольные точки, аренды и единый привязанный к
`sponsor` журнал бюджета сохраняют состояние между перезапусками.

### Допуск платных операций

Текущая модель умеет ограничить полную стоимость транзакции только для
`ethereum`, `polygon` и `bnb`. Для `base`, `arbitrum`, `optimism`, `ink`,
`scroll`, `linea` и `metis` платные действия в рабочем режиме блокируются:
дополнительную комиссию сети нельзя ограничить полями подписанной транзакции.
Для этих записей реестра по-прежнему доступны dry-run и наблюдение в аварийном
режиме.

Даже допустимая модель комиссий не разрешает запуск в промышленной среде. Для
каждой сети нужны доверенный операторский манифест, два независимых RPC для
чтения, отдельный RPC для отправки, проверенная поддержка EIP-7702 и все
остальные условия запуска.
Официальных манифестов репозиторий не предоставляет.

## Безопасная быстрая проверка

Работайте с уже полученным деревом исходников на зафиксированном коммите. Сверьте
версии инструментов с закреплёнными значениями из
[`docs/development/ci.md`](docs/development/ci.md):

```sh
go version
node --version
npm --version
python3 --version
forge --version
actionlint -version
shellcheck --version
govulncheck -version
gitleaks version
slither --version
solc --version
```

Затем выполните только локальные проверки и просмотр справки:

```sh
npm ci
make security-validation
go run ./cmd/guard-daemon --help
```

Эти команды не требуют ключей или настроенных внешних RPC и не запускают демон.
Проверки развёртывания используют только локальный Anvil. Быстрая проверка не
является разрешением на запуск в рабочем режиме.
