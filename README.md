# guard-daemon: безопасное восстановление активов

`guard-daemon` наблюдает за поступлениями на скомпрометированный EVM-аккаунт
(EOA) и пытается перевести разрешённые активы на заранее заданный безопасный
адрес. Комиссии оплачивает отдельная роль sponsor. Для выполнения операции
используется EIP-7702 и контракт `RescuerV2`.

Проект не устраняет компрометацию. Source key остаётся скомпрометированным, и
атакующий может подписывать конкурирующие транзакции и авторизации EIP-7702.
Победа `guard-daemon` не гарантирована. После завершения попыток legacy EOA
нельзя повторно использовать для хранения ценности или новых регистраций.

Успешный receipt, ответы `balanceOf`, события `Transfer` и другая отчётность
контракта токена не доказывают экономическую ценность актива. Результат ERC-20
классифицируется только как `token-reported`.

## Состояние проекта

Репозиторий не заявляет готовность к production. В нём нет официальных
manifests развёртывания и адресов официальных развёртываний. Запись сети во
внутреннем реестре означает только, что конфигурация знает её имя, chain ID,
набор известных токенов и экономический профиль. Это не подтверждает наличие
безопасного контракта, поддержку EIP-7702 конкретной сетью или готовность к
платным операциям.

## Модель работы

Для каждой явно включённой сети демон:

1. сохраняет WebSocket-события как предварительные сигналы;
2. восстанавливает пропуски и подтверждает события по согласованному
   финализированному блоку через два независимых RPC чтения;
3. применяет политику `known-only`, `allowlist` или явный режим `all`;
4. сохраняет кандидатов и инциденты в локальном состоянии;
5. в dry-run выполняет только сетевые чтения и `EstimateGas`;
6. в live-режиме допускает платную попытку только после аттестации, проверки
   signer, лимитов расходов, резерва sponsor и правила ценности токена;
7. после receipt проверяет постусловия, не повышая результат ERC-20 выше
   `token-reported`.

Watcher не получает signer или возможность отправки. Один coordinator на пару
chain+sponsor сериализует nonce и отправку. Постоянная очередь, checkpoints,
leases и единый привязанный к sponsor budget ledger сохраняют состояние между
перезапусками.

### Допуск платных операций

Текущая модель умеет ограничить полную стоимость транзакции только для
`ethereum`, `polygon` и `bnb`. Для `base`, `arbitrum`, `optimism`, `ink`,
`scroll`, `linea` и `metis` платные действия в live блокируются: дополнительную
комиссию сети нельзя ограничить полями подписанной транзакции. Dry-run и
наблюдение в emergency для этих записей реестра остаются возможны.

Даже допустимая модель комиссий не разрешает production-запуск. Для каждой сети
нужны операторский доверенный manifest, два независимых RPC чтения, отдельный RPC
отправки, проверенная поддержка EIP-7702 и все остальные условия запуска.
Официальных manifests репозиторий не предоставляет.

## Безопасная быстрая проверка

Работайте с уже полученным деревом исходников на зафиксированном commit. Сверьте
версии инструментов с закреплёнными значениями из
[`docs/development/ci.md`](docs/development/ci.md):

```sh
go version
node --version
npm --version
python3 --version
forge --version
actionlint -version
shellcheck --version
govulncheck -version
gitleaks version
slither --version
solc --version
```

Затем выполните только локальные проверки и просмотр справки:

```sh
npm ci
make security-validation
go run ./cmd/guard-daemon --help
```

Эти команды не требуют ключей или настроенных внешних RPC и не запускают демон.
Проверки развёртывания используют только локальный Anvil. Быстрая проверка не
является разрешением на live-запуск.
